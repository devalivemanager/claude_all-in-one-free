# 절약 조치 점검표

## 조치 전 — 순서대로

1. **어느 설정 폴더가 실제로 쓰이는가** — `$env:CLAUDE_CONFIG_DIR` 가 비었으면 `~/.claude`. 다른 폴더를 고치면 효과 0
2. **현황을 잰다** — `tools/token-audit.ps1` (읽기 전용)
3. **숫자가 큰 자리를 고른다** — 점검 도구 [1]~[5] 절 중 큰 것, 그 절에 적힌 원칙 번호로 간다. 도구로 못 재는 재작업·읽기·쓰기(1·3·4장)는 늘 점검 대상이다
4. **기대값을 먼저 적는다** — 「무엇이 몇에서 몇으로 줄어야 성공인가」. 실행 뒤에 정하면 무엇이 나와도 성공처럼 보인다

## 조치 후

5. 같은 도구로 **다시 잰다** — 줄었는가
6. **품질이 유지됐는가** — 절약 뒤 재작업이 늘었으면 손해다
7. 새 설정은 **세션을 다시 켜야** 걸린다

## 반년에 한 번 — 죽은 지시어 청소

명령어·도구는 바뀐다. 규칙 파일·에이전트·스킬에 **이미 효과가 없어진 지시**가 남아 있으면 매 세션 토큰만 쓴다.

```bash
# 규칙·에이전트·스킬에서 효과 없는(또는 사라진) 표현 찾기
grep -rn -i -E "think (hard|harder|more)|megathink|TodoWrite|prefill" CLAUDE.md AGENTS.md .claude/ ~/.claude/agents ~/.claude/skills
```
- 걸린 줄이 **변수 이름·설명문**인지(예: `symptoms_prefilled`), 실제 **지시**인지 원문으로 가른다
- 공식 변경 기록(CHANGELOG)·문서의 기준일을 함께 본다 — 「없어졌다던 것이 다시 생기기도」 한다(`ultrathink`)

## 하지 않을 것

- ✗ 안 도는 에이전트의 모델·effort 를 내리고 「절약했다」고 보고
- ✗ 발표 수치를 그대로 기대값으로 쓰기
- ✗ 정밀한 값이 오가는 업무에 손실 압축 도입
- ✗ 기억 색인을 무작정 삭제(탐색 비용이 늘어난다)
- ✗ 표본 하나 열어 보고 전체 일반화(전수로 센다)
