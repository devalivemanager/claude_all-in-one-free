## 0. 구조 — 왜 새는가

Claude Code 는 **매 턴 대화 전체를 다시 입력으로 넣는다.** 앞부분은 프롬프트 캐시로 할인되지만, 대화가 길어질수록 매 턴 들어가는 양 자체가 쌓인다. 그리고 컨텍스트가 찰수록 앞의 지시를 잊고 실수가 는다 `[공식]`. 토큰은 아래 일곱 자리에서 새고, **위에 있을수록 크다.**

| 장 | 새는 자리 | 대표 증상 | 점검 도구 절 |
|---|---|---|---|
| 1 | 재작업 | 틀린 것을 만들고 다시 만들기 · 재요청 | — (습관) |
| 2 | 위임·모델 | 서브에이전트 남발 · 높은 effort | ② effort · ④ 위임 호출 · **token-meter 출력 줄** |
| 3 | 읽기 | 파일·로그 통째 읽기 · 스킬 문서 주입 | — (습관) |
| 4 | 쓰기 | 파일 통째 재작성 · 긴 출력 | — (습관) |
| 5 | 상시 적재 | 규칙 파일 · 기억 색인 · 스킬·MCP 목록 | ③ 상시 적재 |
| 6 | 세션 | 섞인 긴 세션 · 이미지 누적 | ⑤ 세션 · **token-meter 캐시 읽기 줄** |
| 7 | 절약의 함정 | 정밀도 손실 · 엉뚱한 곳 측정 | ① 설정 폴더 |

★「점검 도구 절」은 `tools/token-audit` 출력의 [1]~[5] 절이다(설정·구조를 잰다). **돈이 실제로 어느 줄로 나가는지**는 `tools/token-meter.py` 로 잰다 — 입력·캐시 쓰기·캐시 읽기·출력 네 줄의 **비용 비중**이 큰 줄부터 막는다. 「습관」 장은 이 비중의 변화로 효과를 확인한다.

**요금의 구조** `[실측 역산 — 기록된 청구액과 소수점 여섯째 자리까지 일치]` : 캐시 쓰기는 입력 단가의 **2배**(Claude Code 는 1시간짜리 캐시를 쓴다), 캐시 읽기는 **0.1배**, 생각 토큰은 출력 단가. 그래서 캐시 읽기는 토큰 비중보다 비용 비중이 작지만, **긴 세션에서는 그래도 가장 큰 줄**이 된다.

## 1장. 재작업 — 가장 비싼 낭비

1. **확인 수단을 먼저 준다** — 확인 방법이 없으면 「다 된 것 같다」에서 멈추고, 틀린 것을 사람이 찾아 다시 시키게 된다. 확인 수단 하나로 75→90점 `[외부]`. 단 **검사기는 재는 것만 좋아지게 하므로 「눈으로 볼 곳 3개」** 를 함께 걸고, 끝나는 조건에 **상한**(N번 고쳐도 안 되면 멈추고 보고)을 둔다. ★단 **확인 지시를 겹겹이 붙이지 않는다** — 최신 모델은 스스로 확인하는 편이라 「확인해라·다시 확인해라·한 번 더」는 과잉이고 그만큼 토큰이다 `[외부]`. 확인 수단 **하나** + 결과는 **주장 말고 증거**(무엇을 실행했고 무엇이 나왔나)로 받는다
2. **처음부터 결과 모양 · 건드릴 범위 · 끝 기준을 적는다** — 재요청 한 번이 대화 전체를 한 번 더 읽힌다. 틀은 `02_지시문.md` ①
3. **모호하면 해석을 여러 개 보여 주고 묻는다** — 추측으로 고른 한 갈래가 틀리면 통째로 재작업이다. 질문 한 번이 가장 싸다
4. **새로 만들기 전에 기존 코드·표준 함수부터 찾는다** — 만들기 전 네 번 묻는다 : 존재해야 하나 → 이미 있나 → 표준으로 되나 → 한 줄로 되나
5. **단순함 먼저 · 요청한 것만** — 추측성 기능·한 번 쓰는 추상화·일어날 수 없는 경우의 예외처리를 넣지 않는다
6. **고칠 때는 수술처럼** — 요청한 곳만 바꾸고 기존 스타일을 지킨다. 지우는 것은 **이번 수정으로 안 쓰이게 된 것만**, 원래 있던 죽은 코드는 보고만 한다
7. **변경을 한 문장으로 설명할 수 있으면 계획 단계를 건너뛴다** — 계획에도 고정비가 붙는다. 범위가 불확실하거나 여러 파일을 바꿀 때만 탐색 → 계획 → 구현 `[공식]`
8. **큰 기능은 인터뷰 → SPEC 문서 → 새 세션에서 구현** — 구현 세션이 깨끗한 컨텍스트로 시작한다. 좋은 명세는 관련 파일·범위 밖·끝의 검증 단계를 담는다 `[공식]`
9. **반복 업무는 업무 파일 하나로 적어 둔다** — 목적·시작 조건·입력·단계·결과물·완료 기준·예외. 결과가 틀리면 **채팅이 아니라 파일을** 고친다. 매번 같은 설명을 다시 치지 않는다

## 2장. 위임·모델

10. **위임은 손익분기부터** — 서브에이전트는 프롬프트 캐시를 물려받지 못한다. 소형 과제 : **단독 $0.76 < Haiku 위임 $0.78 < Opus 위임 $1.80**. 대형 과제 : 위임 규율로 **$4.55 → $3.13(31%↓)** `[실측]`. 작은 일은 직접, 큰 일만 위임
11. **비싼 모델은 비용 절감용 위임처가 아니다** — 품질·병렬화·컨텍스트 분리가 목적일 때만
12. **팀은 4역할 안팎, 많아도 8** — 조사·구현·시험·검토. 에이전트 하나마다 고정비가 붙는다 `[외부]`
13. ★**effort(생각 단계)는 기본 낮게, 어려운 단계만 국소적으로 올린다 — 도구보다 큰 지렛대다.** 외부 108회 실측(소넷·과제 6개×3회)에서 **effort 를 낮춘 쪽만 비용 −15.9%**, 절약 도구 4종은 −1.8% ~ **+37.7%** 였고 통과율도 떨어지지 않았다(18/18) `[외부]`. 에이전트 정의의 `effort:` 가 **전역값을 덮어쓴다** — 전역만 보고 정상이라 판정하지 않는다 `[실측]`. 한 번만 더 깊게 생각시키려면 **`ultrathink` 한 단어**를 쓴다 — 「think hard·천천히 생각해」류 문장은 키워드로 인식되지 않아 효과가 없다 `[외부]`. ★거꾸로 **붙여 넣은 글에 `ultrathink` 가 섞여 있으면 의도치 않게 깊은 생각이 켜진다** `[실측]`
14. **비용은 단가가 아니라 끝날 때까지의 총비용** — 같은 90점에 Sonnet 은 확인 3배·시간 5배, 단가는 절반인데 총비용은 Opus 와 비슷 `[외부, 1회]`. 반복 검증이 붙는 일은 싼 모델이 싸지 않을 수 있다
15. **낮은 effort 는 구조로 받친다** — 판단을 검증기로 · 경로·범위를 미리 줘서 탐색을 없앰 · 추론 대신 복제·실측 · 결정은 기록에 고정 · 잘게 쪼개기. 단 **원인 진단·설계 판단·전제 의심**은 낮은 effort 가 위험하다 `[실측]`

## 3장. 읽기

16. **조사 전에 기억·색인부터 본다** — 아는 것을 다시 캐지 않는다
17. **스킬 호출 전 「답이 본문 한 줄인가, 문서 전체가 필요한가」** — 어떤 SDK 스킬은 부르는 순간 문서 약 **18만 토큰** 을 붙였고, 한 세션 비용의 **36.5%** 가 그것이었다 `[실측]`. 가격·모델 ID 같은 한 줄은 웹 검색이 싸다
18. **필요한 것만 읽는다** — 파일은 줄 범위를 지정하고, 코드·JSON·로그 같은 밀집 입력은 검색어·건수·앞뒤 몇 줄로 걸러서 읽는다. 큰 로그 통째 검색은 시간 초과까지 난다 `[실측]`
19. **글 위주 PDF 는 텍스트부터 뽑는다**(PyMuPDF `get_text()` 등). ★**스캔본·화면설계서·도표 PDF 는 텍스트 추출로 내용이 조용히 사라진다** — 추출량이 적으면 렌더해서 본다 `[실측]`
20. **넓은 탐색은 서브에이전트에 맡기되 범위를 먼저 좁힌다** — 「조사해」만 던지면 수백 파일을 읽어 메인 컨텍스트가 찬다. 결론만 표로 돌려받는다 `[공식]`
21. **색인·지도는 범위를 좁힐 뿐, 근거는 원본으로** — 구조 질문을 흐름·연결·역할 셋으로 나눠 읽을 곳을 좁힌다. 코드 지도 도구의 이득은 저장소 규모에 비례한다 — 작은 저장소에 들이면 상시 비용만 는다 `[외부]`
22. **외부 서비스는 CLI 도구로 다룬다**(`gh` 등) — 컨텍스트 효율이 가장 좋다 `[공식]`
23. **큰 공개 문서 학습은 무료 도구(NotebookLM 등)에 맡긴다** — 요약·퀴즈·오디오 개요를 Claude 토큰 없이 얻는다. ★고객사·내부 자료는 올리지 않는다

## 4장. 쓰기

24. **파일을 통째로 다시 쓰지 않는다. 작은 diff 로 고친다** — 출력 토큰 상한 초과의 근본 원인은 상한이 아니라 통째 재작성이다. 상한을 128K 까지 올려도 못 막았다 `[실측]`
25. **큰 단일 파일은 쪼갠다** — 인라인 스크립트를 외부 파일로 빼면 이후 수정이 작아진다 `[실측]`
26. **결과 형식을 고정한다** — 표·틀을 미리 정하면 출력도 「어떻게 보여줄까」 고민도 준다

## 5장. 상시 적재 — 매 세션 내는 고정비

27. **규칙 파일(CLAUDE.md)은 한 장, 200줄 아래, 줄마다 「이걸 지우면 실수가 나는가?」** — 아니면 지운다. 길면 중요한 규칙이 소음에 묻혀 오히려 안 지켜진다 `[공식]`. 처음 만들 때는 `/init` 초안에서 필요한 줄만 남긴다. 200줄 기준은 `[외부]`. 더 과감하게는 **지워 보고 같은 데서 두 번 넘어질 때만 되살린다** — 외부 실험에서 규칙을 켠 쪽이 규칙 문서를 한 번도 열지 않았고 품질은 같았으며 입력 토큰만 34~56% 늘었다 `[외부]`
28. **가끔 쓰는 지식은 스킬로, 반드시 지킬 것은 훅으로** — 스킬은 필요할 때만 본문이 실리고, 훅은 규칙과 달리 결정론적이다 `[공식]`
29. **도구는 겹치지 않게, 설치 전 상시 비용을 숫자로** — 예 : Superpowers 약 584토큰 vs ECC 약 24,048토큰 `[외부]`. 무료라고 공짜가 아니다
30. **안 쓰는 스킬은 끈다** — 프로젝트 `.claude/settings.json` 에 `"skillOverrides": { "스킬이름": "off" }`. 109개를 끄고 세션당 약 3,100토큰 `[실측]`(설정 파일에서 109개 확인 · 점검 도구 [3] 절에 개수가 나온다). 단 **라우터형 플러그인**(본문 한 줄, 하위는 요청 시 로딩)은 꺼도 절약 0, 기능만 잃는다 `[실측]`
31. **MCP 서버는 쓸 때만 켠다** — 도구 정의가 세션에 실린다. 단 도구 **지연 로딩**이 켜진 환경에서는 처음엔 **이름만** 실리고 쓸 때 정의를 불러온다 `[실측: 작성자 데스크톱 앱 세션]` — 이 경우 끄는 효과가 작다. 자기 환경이 어느 쪽인지는 `/context` 로 확인한다
32. **기억 색인은 무작정 깎지 않는다** — 색인이 있어야 아는 것을 다시 캐지 않는다. 줄이면 입력은 줄고 탐색이 는다 `[실측]`. 상한을 정하고(예 25,600B) 넘으면 **설명 줄을 줄이거나 오래된 상세를 별도 문서로 이관**한다(실례 : 123KB 일지 → 6.7KB 요약 + 이관본) `[실측]`

## 6장. 세션 — 누적

33. ★**주제가 바뀌면 새 세션**(또는 `/clear`). **정정이 2번 실패해도 새로 시작한다** — 실패한 시도로 컨텍스트가 더러워졌다 `[공식]`. 돈으로 보면 이것이 가장 큰 줄이다 : 긴 세션에서는 **캐시 읽기가 토큰의 99%, 비용의 77~79%** 였다(단가가 입력의 1/10 인데도) `[실측: token-meter]` — 같은 일을 해도 응답 1건당 비용이 세션이 길수록 오른다
34. **세션 파일이 3,000줄을 넘으면 무거워지고, 5,000줄 이상이면 보관 대상** `[실측]` — 체감 속도는 파일 크기보다 줄(항목) 수가 정했다. 보관은 파일 이동이 아니라 **앱의 보관 기능**으로
35. **스크린샷은 대화에 싣지 말고 경로로 참조** — 세션 파일 하나가 82.6MB 였고 그중 **71% 가 이미지 base64** 였다 `[실측]`
36. **곁가지 질문은 `/btw`, 압축은 지시를 붙여 `/compact`** — `/btw` 답은 대화 이력에 남지 않는다. 압축 때 「수정한 파일 목록과 검증 명령은 보존」을 붙인다 `[공식]`

## 7장. 절약의 함정 — 절약이 손해가 되는 자리

37. **정밀도를 깎는 절약은 절약이 아니다** — 오래된 문맥을 이미지로 압축하는 프록시류는 식별자·숫자를 잘못 읽을 수 있다. 오독 한 번의 재작업이 절약분보다 크다
38. **「몇 개를 바꿨나」가 아니라 「실제로 실리는가」** — 안 도는 에이전트를 내려 봐야 0(호출 기록 실측 : 설계 계열 12종 **0건**) · 다른 설정 폴더(`CLAUDE_CONFIG_DIR`)를 고쳐 봐야 0 `[실측]`
