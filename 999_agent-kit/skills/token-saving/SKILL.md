# 토큰 절약

> 이 폴더 하나에 절차(이 파일)·원칙·지시문·점검표·도구가 모두 들어 있다(v1.0, 2026-10-02). 사람이 처음 읽을 안내는 `README.md`다.
> `<스킬폴더>`는 이 폴더를 복사해 둔 자리다(예 : `~/.claude/skills/token-saving`). 원칙 번호·근거 수치는 `01_원칙_정수.md`를 본다.

**한 줄 원칙** : 어디서 새는지 먼저 재고, 그 자리 하나만 막고, 다시 잰다. 정밀도를 깎는 절약은 절약이 아니다.

## 1. 평소 작업 습관 (도구로 못 재는 자리 · 효과 큰 순서)

1. **재작업을 먼저 막는다** — 과제·지켜야 할 선·확인 방법·끝나는 조건을 갖추고 시작한다. 모호하면 해석을 보여 주고 묻는다(질문 한 번이 가장 싸다). 끝나는 조건에는 상한(N번 고쳐도 안 되면 멈추고 보고)을 둔다
2. **위임은 손익분기부터** — 서브에이전트는 프롬프트 캐시를 물려받지 못한다. 파일 몇 개짜리 일은 직접 한다. 넓은 탐색만 범위를 좁혀 맡기고 결론은 표로 받는다. 대량 분류·거르기(수백 건의 예/아니오·유형 판정)는 Haiku 서브에이전트에 묶어서 맡긴다
3. **조사 전에 기억·색인부터** — 아는 것을 다시 캐지 않는다
4. **필요한 것만 읽는다** — 줄 범위 지정, 로그·JSON은 검색어로 걸러 건수와 앞뒤 몇 줄만. 0건이면 「없다」 전에 검색 범위를 의심한다
5. **스킬을 부르기 전에** — 답이 한 줄(가격·모델 ID 등)이면 문서 전체를 붙이는 스킬 대신 웹 검색이 싸다
6. **쓰기는 작은 diff** — 파일을 통째로 다시 쓰거나 채팅에 통째로 출력하지 않는다. 큰 단일 파일은 쪼갠다. 이번 변경 때문에 안 쓰이게 된 것만 지우고, 원래 있던 죽은 코드는 언급만 한다
7. **스크린샷은 경로로 참조** — 대화에 이미지를 쌓지 않는다
8. **주제가 바뀌거나 정정이 2번 실패하면** 새 세션을 권한다. 넘길 것은 10줄 이내 파일로 남긴다

## 2. 사용자가 「토큰 절약 조치」를 요청했을 때

1. **실제 설정 폴더 확인** — `CLAUDE_CONFIG_DIR`가 비었으면 `~/.claude`. 다른 폴더를 고치면 효과 0
2. **현황 측정 (읽기 전용)**
   - Windows : `powershell -ExecutionPolicy Bypass -File <스킬폴더>\tools\token-audit.ps1 -ProjectDir <프로젝트>`
   - macOS·Linux·Git Bash : `bash <스킬폴더>/tools/token-audit.sh <프로젝트>`
   - 돈이 어느 줄로 나가는지 : `python <스킬폴더>/tools/token-meter.py <프로젝트> --days 7`. 결과는 비용 비중(cost%)이 가장 큰 줄부터 본다(출력 줄이면 effort·답 길이, 캐시 읽기 줄이면 세션 길이·상시 적재 파일, 캐시 쓰기 줄이면 큰 파일 읽기·문맥 재시작)
3. **[1]~[5] 절 중 숫자가 큰 절 하나**를 고른다. 절 제목 끝 「→ principles N」이 볼 원칙이다
4. **기대값을 먼저 적는다** — 무엇이 몇에서 몇으로 줄어야 성공인가
5. **조치는 하나만** → 같은 도구로 다시 잰다 → 품질(재작업)이 유지됐는지 본다 → 새 설정은 세션 재시작 후 걸린다고 알린다

| 절 | 새는 자리 | 대표 조치 |
|---|---|---|
| [2] effort | 높은 effort | 기본은 낮게, 어려운 단계만 국소적으로. **에이전트 정의의 `effort:`가 전역값을 덮어쓴다** |
| [3] 상시 적재 | CLAUDE.md·MEMORY.md·스킬·MCP | 규칙은 「지우면 실수가 나는가」로 거른다. 안 쓰는 스킬은 끈다. MCP는 지연 로딩 여부를 `/context`로 먼저 확인 |
| [4] 위임 호출 | 실제로 도는 서브에이전트 | 정의 개수가 아니라 **호출 기록**(`subagents/*.meta.json`)으로 판정 |
| [5] 세션 | 줄 수 3,000+ 무거움 · 5,000+ 보관 | 앱의 보관 기능으로 정리. 이미지 누적 확인 |

## 3. 하지 않을 것

- 안 도는 에이전트의 effort·모델을 내리고 「절약했다」고 보고
- 다른 곳에서 발표한 수치를 그대로 기대값으로 쓰기 · 표본 하나로 일반화(전수로 센다)
- 정밀한 값(식별자·숫자)이 오가는 일에 손실 압축 도입
- 기억 색인을 무작정 삭제(탐색 비용이 늘어난다)
- 단가만 보고 싼 모델 선택 — **끝날 때까지 든 총비용**으로 본다

## 4. 도구 사용 시 주의

- `apply-token-saving.ps1`은 설정을 바꾸는 도구다. 실행 전 `-WhatIf`로 대상을 보여 주고 사용자 확인을 받는다. 바꾸기 전에 자동으로 백업하며, 적용 후 세션을 다시 켜야 걸린다
  - `settings.json`은 최상위 `effortLevel` 값 한 곳만 바꾸고, `modelSettings`가 없을 때만 그 블록을 넣는다. 파일은 BOM 없이 쓴다. 스크립트 머리 주석에 「2026-10-04 수정」이 없으면 옛 판이므로 쓰지 않는다
- ★**Opus 5.5와 그 이후 모델은 사용자 설정의 최상위 `effortLevel`을 무시한다**(2026-10-04 공식 문서 확인). effort를 낮출 때는 `modelSettings` → `"claude-opus-5-5": { "effortLevel": "low" }`로 건다(또는 프로젝트 설정의 최상위 키·`CLAUDE_CODE_EFFORT_LEVEL`). 점검할 때 최상위 키만 보고 「low로 정상」이라 판정하지 않는다
- 원칙 26의 `skillOverrides` 키는 키트에 `[실측]`으로 적혀 있으나 공식 문서 대조는 `[확인 못 함]`
- 프로젝트마다 켜 둘 스킬·플러그인을 고르는 대시보드(Agent HUD)는 **macOS 전용**이다. 다른 OS에서는 원칙 26(프로젝트별 끄기)과 `token-audit` [3] 점검으로 대신한다
