# 토큰을 아끼는 지시문 7개 — 그대로 붙여 쓴다

## ① 일 맡길 때 4줄 틀 (재요청을 없앤다)

재요청이 생기는 원인은 빠진 요소 때문이다. 재요청 한 번이 전체 대화를 한 번 더 읽힌다.

```
[과제] 결과물 한 줄
[지켜야 할 선] 하면 안 되는 것 2~3개 (예: 파일 통째 재작성 금지, 범위 밖 수정 금지)
[확인 방법] 맞았는지 알 기준·예시·비교할 원본, 그리고 끝내기 전 눈으로 볼 곳 3개
[끝나는 조건] 기준 통과 또는 N번 고쳐도 안 되면 멈추고 무엇이 막혔는지 보고
```

## ② 조사를 맡길 때 (메인 컨텍스트를 지킨다)

```
서브에이전트로 조사해. 범위는 <폴더/파일>로 한정한다.
읽기 전용이다. 결과는 아래 표 하나로만 돌려줘(1,500자 이내):
| 항목 | 판정 | 근거(파일:행) | 남은 일 |
「비슷한 코드가 있다」만으로 판정하지 말고 그 코드가 증상을 막는 이유를 적어라.
```

## ③ 파일을 고칠 때

```
기존 파일은 작은 diff 로만 고쳐라. 파일 전체를 다시 쓰거나 채팅에 통째로 출력하지 마라.
한 번에 하나만 바꾸고, 바꿀 때마다 실행해서 확인해라.
```

## ④ 로그·큰 출력을 볼 때

```
로그는 통째로 읽지 말고 <검색어>로 거른 뒤 건수와 앞뒤 10줄만 보여줘.
결과가 0건이면 「없다」고 하지 말고 검색 범위와 검색어가 맞는지 먼저 의심해라.
```

## ⑤ 규칙 파일 다이어트 (보리스 방식, 외부 키트)

```
CLAUDE.md 를 CLAUDE.md.bak 으로 이름만 바꿔 백업해. 지우지 마.
백업 안의 규칙을 한 줄씩 번호 붙여 보여 줘.
앞으로 며칠 규칙 없이 일한다. 내가 "또 틀렸다"고 하면 그게 몇 번 규칙과 관련 있는지
rules-log.md 에 날짜와 한 줄로 적어. 같은 번호가 두 번 이상 적힌 규칙만 되살려.
```
체크 : 되살린 줄이 원래의 절반을 넘으면 기준이 느슨한 것이다.

## ⑥ 세션을 정리할 때

```
이 세션에서 결정한 것과 남은 일을 <파일>에 10줄 이내로 남겨.
다음 세션은 그 파일만 읽고 이어간다.
```
→ 그다음 `/clear` 또는 새 세션. 압축이 필요하면 `/compact 수정한 파일 목록과 검증 명령은 반드시 보존`.

## ⑦ 어떤 AI 에나 통하는 공통 6원칙 틀 (Anthropic 프롬프트 모범사례 요지)

모델이 바뀌어도 그대로인 칸이다. 한 번에 제대로 시키면 재요청(= 대화 전체 재열람)이 준다.

```
<역할> 어떤 입장에서 답할지 한 문장 </역할>

<자료>
(긴 자료·문서·로그는 위에 둔다)
</자료>

<예시>
잘된 예시 3~5개 (나쁜 예시보다 좋은 예시)
</예시>

<지시>
무엇을 할지 분명하게 + 왜 그런지 맥락까지 (이유를 알면 경계 사례를 스스로 판단한다)
</지시>

<질문> 마지막 줄에 묻는다 </질문>
```

요점 : ① 분명하게 ② 왜 그런지 ③ 예시 3~5개 ④ 지시와 자료를 태그로 갈라 섞이지 않게 ⑤ 역할 한 문장 ⑥ **긴 자료는 위, 질문은 아래**.
