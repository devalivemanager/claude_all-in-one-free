# 지시문 5개 — 그대로 붙여 쓴다

## Ⓐ 첫 분석 (지금 세션)

```
[과제] chunks/ 의 자막을 읽고, 시청자가 따라 해야 하는 단계를 순서대로 뽑아라.
[지켜야 할 선] 자막에 없는 단계를 채워 넣지 마라. 화면에만 나올 것 같은 값(코드·설정)은
「화면 확인 필요」로 표시하고 지어내지 마라. 자막 문장을 그대로 옮기지 말고 요약하라.
[확인 방법] 단계마다 근거가 된 자막 시각(예: 03:15)을 붙여라.
[결과 모양] analysis_A.md 에 표 하나 : | # | 단계 | 확인 방법 | 근거 시각 |
[끝나는 조건] 모든 구간을 다 읽었으면 끝. 표 아래에 「영상이 다루지 않은 것」 3줄.
```

## Ⓑ 독립 분석 (새 컨텍스트 · 가능하면 다른 모델)

```
서브에이전트로 돌려라(가능하면 Ⓐ 와 다른 모델). 이 지시만 넘긴다 — analysis_A.md 는 넘기지 마라.

[과제] chunks/ 의 자막만 읽고 시청자가 따라 해야 하는 단계를 순서대로 뽑아라.
[지켜야 할 선] 다른 분석 파일을 열지 마라. 자막에 없는 단계는 넣지 마라. 원문을 옮기지 말고 요약하라.
[확인 방법] 단계마다 근거 자막 시각을 붙여라.
[결과 모양] Ⓐ 와 같은 표 형식을 **최종 답변 텍스트로** 돌려준다.
```

★받은 텍스트는 **메인 세션이 `analysis_B.md` 로 저장**한다. 환경에 따라 서브에이전트의 보고서 파일 쓰기가 막혀 있다(실전 시험에서 실제로 거부됨). 파일로 쓰라고 시키면 실패하거나, 우회 경로로 쓰려다 엉뚱한 곳을 건드린다.

## Ⓒ 병합

```
analysis_A.md 와 analysis_B.md 를 비교해 merged.md 를 만들어라.
- 두 분석에 다 있는 단계 → 「확정」
- 한쪽에만 있는 단계 → 「보류」. 근거 시각의 자막 원문을 다시 읽고 실제로 있으면 확정, 없으면 삭제
- 순서·값이 서로 다르면 → 「충돌」. 자막 원문으로 판정하고 판정 근거를 한 줄로
- 둘 다 「화면 확인 필요」로 남긴 값(명령 철자 등)은 **제3 출처**(공식 문서·도구의 --help)로 확인되면 채우고 출처를 적는다. 확인 못 하면 그대로 남긴다
- 끝까지 못 정한 것은 억지로 합치지 말고 두 갈래로 나눠 남겨라
  · 「확인 필요(정보)」 : 자료가 모자라 못 정한 것 — 화면에만 있는 값, 원문·공식 문서 확인 못 함. 무엇을 보면 풀리는지 한 줄
  · 「확인 필요(판단)」 : 사실은 다 모였지만 사람이 정할 것 — 채택 여부, 약관·라이선스 해석, 비용 감수
결과 끝에 확정 N · 보류→확정 N · 삭제 N · 충돌 N · 확인 필요(정보) N · 확인 필요(판단) N 을 숫자로 적어라.
```

> 두 갈래 구분과 아래 「판정자 독립」은 후츠릿 「AI끼리 협업시키면 결과가 별로인 이유」의 교차검증 6전략 중 5·6번에서 가져왔다.
>
> **판정자 독립** : 병합은 보통 Ⓐ(메인)가 한다. 판정 기준이 「자막 원문」이라는 바깥 기준이라 괜찮다. 그러나 **사실 대조가 아니라 의견 판단**(「이 도구를 쓸까」, 「어느 방법이 나은가」)을 병합할 때는 Ⓐ가 판정자를 겸하지 말고 **세 번째 눈**(Ⓐ·Ⓑ와 다른 모델의 서브에이전트, 또는 사용자)에게 두 분석을 함께 보여 판정받는다. 두 분석이 처음부터 완전히 같은 판단이면 「둘 다 같은 곳을 놓쳤나」를 한 번 더 본다.

## Ⓒ-1 덮고 답해 볼 질문 (선택)

```
정리본 끝(Self-Critique 앞)에 「## 덮고 답해 보기」 절을 두고 질문 2~3개를 단다.
- 묻는 것 : 내 판단(쓸까 말까와 그 이유), 영상이 놓친 함정, 내 작업에 쓸 곳
- 묻지 않는 것 : 숫자·이름·날짜 암기(찾아보면 되는 것)
- 답은 <details><summary>답</summary> … </details> 로 접고, 본문 어느 절에 근거가 있는지 적는다
- 일반 지식으로 답이 나오는 질문은 버린다 → 내 결정, 다른 정리본과의 연결을 묻는다
- 답은 한두 문장(나열이 필요하면 질문을 좁힌다). 질문에 정답을 넣지 않는다
- 본문에서 [추측]·제안인 것은 답에서도 그렇게 적는다
```

> 근거 : 인출 연습(덮고 떠올리기) 공부법. 작성자도 아직 효과를 시험하는 중인 선택 단계다.

## Ⓓ 스킬 포장

```
merged.md 의 확정 단계만으로 templates/SKILL_template.md 틀을 채워
<스킬이름>/SKILL.md 를 만들어라. (자주 쓸 스킬만 .claude/skills/ 에 둔다 — 스킬 목록은 매 세션 실려 토큰을 쓴다.
가끔 쓸 것은 다른 폴더에 두고 필요할 때 읽게 한다)
- description 은 「~할 때 쓴다」 한 줄로 구체적으로
- 단계마다 확인 방법을 넣는다
- 「확인 필요」로 남은 단계는 그대로 표시한다
- 출처(영상 제목·주소·날짜)를 맨 아래에. 자막 원문은 넣지 않는다
```

## Ⓔ 실전 시험

```
방금 만든 스킬을 실제 입력 <예: 내 프로젝트의 ○○ 파일> 로 한 번 돌려라.
단계별로 됨/안 됨과 증거(실행한 명령·결과)를 적고,
안 된 단계는 SKILL.md 를 고쳐라(채팅으로 고치지 말고 파일을).
두 번 고쳐도 안 되면 멈추고 무엇이 막혔는지 보고하라.
사람이 앱에서 직접 조작해야 하는 단계(슬래시 명령·설정 화면)는 실행 대신 「사람 조작 단계」로 표시하고,
확인 방법이 맞는지만 점검하라.
```
