# 유튜브 영상 → 학습·스킬

> 이 폴더 하나에 절차(이 파일)·원칙·지시문·틀·도구가 모두 들어 있다(v1.0, 2026-10-03). 사람이 처음 읽을 안내는 `README.md`다.
> `<스킬폴더>`는 이 폴더를 복사해 둔 자리다(예 : `~/.claude/skills/youtube-to-skill`). 지시문 원문은 `02_지시문.md`를 본다.

**한 줄 원칙** : 영상을 두 번 독립적으로 분석해서 **두 번 다 나온 내용만 믿는다.** 한 번만 나온 내용은 모델이 지어냈을 가능성이 높다.

## 언제 쓰나 / 범위 밖

- 쓴다 : 따라 하기 영상(튜토리얼)의 절차를 파악하거나, 다시 쓸 스킬로 바꿀 때
- 범위 밖 : 코드·설정값이 **화면에만** 나오는 영상의 값 복원(자막만으로는 불가 → 「화면 확인 필요」로 남긴다). 영상 다운로드

## 단계

| # | 할 일 | 됐는지 확인하는 법 |
|---|---|---|
| 0 | **이미 학습했는지 확인** — 링크에서 영상 ID(11자, 쇼츠·`si=` 같은 꼬리 무시)를 뽑아 정리본을 모아 두는 폴더에서 검색한다. 있으면 분석을 다시 돌리지 말고 기존 정리본을 요약해 알려 준다(같은 영상이 두 번 들어오는 일이 실제로 있었다) | 검색 결과 0건이거나, 기존 정리본 경로를 보고에 적었다 |
| 1 | **자막 준비** — `python <스킬폴더>/tools/yt_transcript.py <영상주소 또는 transcript.txt> --chunk 10 --out <작업폴더>`. 주소면 yt-dlp 로 자막만 받는다(`pip install yt-dlp` 필요, 없으면 붙여 넣은 자막 파일을 쓴다). 429 가 나면 몇 분 기다리거나 `--lang ko` 하나만, 그래도 안 되면 사용자에게 「스크립트 표시」 복사본을 받는다 | `<작업폴더>/chunks/chunk_NN.txt` 가 생겼고 줄마다 `[mm:ss]` 시각이 붙어 있다 |
| 2 | **Ⓐ 첫 분석(메인 세션)** — 구간 파일을 모두 읽고 따라 할 단계를 뽑는다. 자막에 없는 단계·화면에만 있을 값은 지어내지 않는다 | `analysis_A.md` 에 `| # | 단계 | 확인 방법 | 근거 시각 |` 표 + 「영상이 다루지 않은 것」 3줄 |
| 3 | **Ⓑ 독립 분석(새 컨텍스트)** — 서브에이전트(가능하면 다른 모델, 예: Ⓐ 가 Opus 면 Sonnet)에 **Ⓐ 결과를 넘기지 않고** 같은 과제를 준다. 결과는 **최종 답변 텍스트로** 받고 메인이 `analysis_B.md` 로 저장한다(서브에이전트의 파일 쓰기는 막힐 수 있다) | Ⓑ 가 다른 분석 파일을 열지 않았고, 같은 표 형식이다 |
| 4 | **Ⓒ 병합** — 둘 다 있음 = 확정 · 한쪽만 = 보류 → 근거 시각의 자막 원문을 다시 읽어 확정/삭제 · 서로 다름 = 충돌 → 원문으로 판정. 둘 다 비워 둔 명령 철자는 공식 문서·`--help` 같은 **제3 출처**로 채우고 출처를 적는다. 못 정한 것은 **「확인 필요(정보)」**(자료 부족 — 무엇을 보면 풀리는지)와 **「확인 필요(판단)」**(사람이 정할 것 — 채택·약관 해석·비용)으로 나눠 남긴다 | `merged.md` 끝에 확정·보류→확정·삭제·충돌·확인 필요(정보)·확인 필요(판단) 개수가 숫자로 있다 |
| 4-1 | **덮고 답해 볼 질문** — 정리본 끝(Self-Critique 앞)에 `## 덮고 답해 보기` 절을 두고 질문 2~3개를 단다. 답은 `<details>` 로 접는다. 질문은 **내 판단·함정·쓸 곳**을 묻고, 숫자·이름 암기와 일반 지식으로 답이 나오는 것은 묻지 않는다. 답은 한두 문장, 질문에 정답을 넣지 않는다(인출 연습, 선택 단계) | 질문마다 정리본 본문에 답의 근거가 있다 |
| 5 | **Ⓓ 포장(스킬로 만들 때만)** — 확정 단계만으로 이 폴더의 `templates/SKILL_template.md` 틀을 채운다. description 은 「~할 때 쓴다」 한 줄, 단계마다 확인 방법, 「확인 필요」는 그대로 표시, 맨 아래 출처(제목·주소·날짜·교차 검증 숫자) | `SKILL.md` 에 자막 원문 인용이 없다 |
| 6 | **Ⓔ 실전 시험** — 만든 스킬을 실제 입력으로 한 번 돌린다. 단계별 됨/안 됨과 증거를 적고, 안 된 단계는 **파일을** 고친다. 앱에서 사람이 조작할 단계는 「사람 조작 단계」로 구분 | 시험 기록이 남았다. 시험 전에는 「완성」이라 보고하지 않는다 |

**학습만 원할 때**(스킬 불필요)는 1~4단계까지 하고, 확정 단계를 사용자에게 보고한다.

## 지킬 것

- **독립성** : Ⓑ 에게 Ⓐ 를 보여 주지 않는다. Ⓐ 를 끝내기 전에 Ⓑ 결과를 먼저 보지 않는다
- **판정자 독립** : 사실 대조(자막 원문에 있나)는 Ⓐ가 병합해도 된다. **의견 판단**(도구 채택, 방법 비교)을 병합할 때는 Ⓐ가 판정을 겸하지 말고 세 번째 눈(Ⓐ·Ⓑ와 다른 모델의 서브에이전트 또는 사용자)에게 맡긴다. 처음부터 완전히 같은 판단이 나오면 둘 다 같은 곳을 놓쳤는지 한 번 더 본다. 근거 : 키트 `02_지시문.md` Ⓒ
- **긴 영상은 구간으로** — 한 번에 넣으면 가운데를 흘린다(기본 10분 단위)
- **저작권** : 자막은 분석용으로만 쓴다. 스킬·문서에는 절차를 **자기 말로** 쓰고 출처를 남긴다. 공개 배포 스킬이면 원 제작자의 허락 조건을 확인한다
- **스킬 위치** : 자주 쓸 스킬만 `~/.claude/skills/` 에 둔다(목록이 매 세션 실린다). 가끔 쓸 것은 다른 폴더에 두고 필요할 때 읽는다
- 위임 손익분기 원칙(`token-saving` 스킬)의 예외다 — Ⓑ 의 목적은 비용이 아니라 **교차 검증용 독립 컨텍스트**다

## 막히면

- 자막을 못 받으면 사용자에게 「…더보기 → 스크립트 표시」 복사본을 요청한다
- 같은 단계가 두 번 실패하면 멈추고 무엇이 막혔는지 보고한다
