# 원칙 — 영상을 스킬로 바꿀 때

## 1. 왜 두 번 분석하는가

모델은 자막에 없는 단계를 그럴듯하게 **채워 넣는다.** 한 번 분석한 결과만 보면 무엇이 영상에 있었고 무엇이 지어낸 것인지 가를 수 없다.

- **두 번 다 나온 내용** → 실제로 영상에 있던 것
- **한 번만 나온 내용** → 지어낸 쪽에 가깝다 → 자막 원문의 **시각**으로 재확인하거나 뺀다

두 분석은 **서로 독립이어야** 의미가 있다.

| 지킬 것 | 이유 |
|---|---|
| Ⓑ 는 **새 컨텍스트**에서 돌린다(서브에이전트·새 세션) | 같은 대화 안이면 Ⓐ 결과를 이미 보고 따라간다 |
| Ⓑ 에게 Ⓐ 결과를 **보여 주지 않는다** | 보여 주는 순간 교차 검증이 아니라 받아쓰기가 된다 |
| Ⓐ 를 끝내기 전에 Ⓑ 결과를 **먼저 보지 않는다** | 반대 방향도 같은 오염이다 |
| 가능하면 **다른 모델**로 Ⓑ | 같은 계열 모델은 맹점이 겹친다. 다른 회사 모델이면 더 독립적 |

## 2. 하지 말 것

1. **긴 영상을 한 번에 넣지 않는다** — 가운데를 흘린다. 10분 안팎 구간으로 나눠 분석하고 구간별 결과를 합친다
2. **분석만 하고 「완성」이라 하지 않는다** — 만든 스킬을 **실제 입력**으로 한 번 돌려 봐야 완성이다
3. **스킬에 영상 자막을 그대로 붙이지 않는다** — 단계는 **자기 말로 요약**한다(아래 저작권)
4. **화면에만 나오는 내용을 자막에서 찾지 않는다** — 코드·설정값이 화면에만 있으면 자막 분석은 「여기서 화면 확인 필요」로 표시하고 넘어간다. 지어내서 채우지 않는다

## 3. 저작권

- 자막은 영상 제작자의 저작물이다. **분석용으로만** 쓰고, 자막 원문이나 긴 인용을 스킬·문서에 옮겨 배포하지 않는다
- 스킬에는 **절차를 자기 말로** 쓰고, 출처(영상 제목·주소·날짜)를 남긴다
- 공개 배포할 스킬이면 원 제작자의 허락 조건(설명란·라이선스)을 확인한다

## 4. 좋은 스킬의 조건

- **언제 쓰는지**(description)가 구체적이다 — 「~를 할 때」 한 줄
- 단계마다 **확인 방법**이 있다 — 그 단계가 됐는지 무엇을 보면 아는가
- **범위 밖**이 적혀 있다 — 이 스킬이 하지 않는 것
- 영상에서 **보류된 단계**는 「확인 필요」로 남긴다
