# 작은 인디 게임 기획·제작·출시 점검

> 근거 : 이 묶음의 `999_document/02_게임개발/게임개발_핵심정리.md`(사례 50여 편 종합). 각 항목의 「사례 n」은 그 문서에서 같은 교훈이 따로 나온 횟수다
> 엔진별 함정은 `godot-pitfalls`, `unity-pitfalls` 스킬이 맡는다. 이 스킬은 **엔진과 상관없는 기획·검사·출시 판단**만 다룬다

## 언제 쓰나 / 범위 밖

- 쓴다 : 새 게임을 시작할 때, 만들던 게임의 범위가 커질 때, 출시 직전 점검
- 범위 밖 : 엔진 문법·설정(엔진별 스킬), 개인 맞춤 수익 예측

## 1. 기획서 첫 장 (만들기 전에 반드시 채운다)

| 칸 | 채우는 법 | 됐는지 확인 |
|---|---|---|
| 재미 한 줄 | 「무엇을 해서 어떤 기분이 드는가」 한 문장. AI 지시문 맨 위에도 둔다 | 한 문장이고, 기능 이름이 아니라 느낌이 들어 있다 |
| 참고 게임 하나 | 이미 되는 게임의 **장르·방식만** 가져온다 | 이름·캐릭터·그림·소리·화면 구성은 새로 만든다고 적혀 있다 |
| 내 소재 | 남이 못 하는 소재(내 직업, 내 취미) | |
| 제약 조건표 | 인원·하루 가능 시간·엔진·무료 상업 도구·장비·기간 | 기간이 **한두 달 이내**(사례 7 : 작게, 끝까지) |
| 뺄 것 목록 | 이번 판에 **만들지 않을 것**과 이유 | 3개 이상 |
| 완성 기준 | 「무엇이 되면 출시」 한 줄 | 사람이 확인할 수 있는 문장이다 |

## 2. 만드는 순서

1. **네모 상자 POC** — 도형만으로 재미 한 줄을 하루 안에 확인한다(사례 4). 크기·카메라 감각이 안 오면 코드로 임시 그림
2. **짧은 판 + 다시 할 이유** — 한 판 길이(1~3분)와 해금·기록·하루 한 판 중 하나 이상(사례 5)
3. **스타일 기준표** — 팔레트·크기·선 굵기를 먼저 고정하고 지시문 파일로 매번 붙인다. 「구하기」보다 「한 스타일로 끝까지」가 어렵다(사례 6)
4. **AI와 일하는 규칙**(사례 8)
   - 기획서·`plan.md`를 먼저 쓰게 하고 바뀔 때마다 갱신
   - 기능은 한 번에 하나, 되돌릴 수 있게(자주 커밋)
   - AI가 엔진을 직접 실행하고 오류를 읽어 고치게 한다
   - **UI는 캡처로 지시**하고 확정 배치는 수치로 기록, **디버깅이 막히면 사람이 원인 가설**을 준다(사례 5)
5. **시행착오는 md로** — 같은 실수가 두 번 나오면 엔진별 스킬로 올린다

## 3. 검사 (네 겹)

| 겹 | 하는 일 | 놓치기 쉬운 점 |
|---|---|---|
| 자동 검사 | 규칙·계산 테스트, 봇이 끝까지 플레이 | 통과해도 「보기 좋음」은 보장하지 않는다 |
| 시각 검사 | 캡처로 화면 확인 | 정지 화면만 보면 움직임이 어색한 것을 못 잡는다 |
| **사람 연속 재생 판정** | 애니메이션·조작감은 사람이 이어서 보고 판정. 「어색하다」는 느낌은 AI에게 **숫자로 번역**하게 시킨다(기울기·보폭·속도) | AI의 「안 맞는다」 의견은 참고, 최종 판정은 사람 |
| 배포본 확인 | 웹·휴대폰 실기에서 한 번 더 | 한글 깨짐·압축 설정 문제는 배포본에서만 보였다 |

- 장치를 걸었으면 **일부러 버그를 심어** 검사가 실제로 실패하는지 확인한다

## 4. 지키는 선 (사례 8)

- 유명 게임·캐릭터·영화·실존 인물 금지. 팬 게임은 팔 수 없다
- 「무료」와 「상업 이용 가능」은 다르다 → 외부 에셋을 하나라도 쓰면 `LICENSES.md`(파일명·출처 주소·라이선스·받은 날짜)
- AI 생성물은 판매처의 AI 사용 공개 기준대로 표기
- 원본은 늘 로컬 PC 파일로, 엔진·도구는 묶이지 않는 쪽(MIT 등)

## 5. 출시와 숫자

- 경로 : **웹(itch.io·크레이지게임즈)에서 지표 → 안드로이드 → 스팀**
- 웹 지표 읽는 순서 : 클릭률 → 첫 판 이탈 → 플레이 시간 → 재방문
- 다른 사람의 성공 숫자는 조건까지 확인한다 : 하루 매출을 한 달로 늘린 추정인지, 선택 편향이 있는지, 협찬 영상인지
- 만드는 과정 공개가 곧 홍보 : 개발 일지 → 블로그 → 전자책(`publishing-workflow` 스킬)

## 끝나는 조건

기획서 첫 장 6칸이 채워졌고, POC로 재미 한 줄을 확인했으며, 출시 전 네 겹 검사와 `LICENSES.md`가 끝났다. 시험 전에는 「완성」이라 보고하지 않는다.
