# 게임 개발 핵심 정리 : AI 도구로 작은 인디 게임 만들기

AI 코딩 도구(클로드 코드 등)로 작은 인디 게임을 처음 만들어 보려는 사람을 위해, 영상·글 사례 약 50편과 작성자가 직접 만든 샘플 게임 기록에서 바로 쓸 교훈만 추렸다.
기획 → 엔진 → 제작(AI·그림·소리·연출) → 시험 → 출시 → 저작권 순서로 읽으면 된다.

- 근거 표시 : `[실측]` 작성자가 직접 확인 · `[추측]` 작성자 판단 · `[확인 못 함]` 원문에 없거나 대조하지 못함. 「사례 n」은 같은 교훈이 따로 나온 횟수다
- 비용·요금·세율·판매량은 모두 출처가 발표한 값이고 작성 시점(2026-10) 기준이다. 쓰기 전에 공식 안내로 다시 확인한다

## 1. 기획

### 1-1. 작게, 끝까지(사례 7)
- 700시간 들인 게임보다 기분 전환으로 3주 만에 만든 게임이 반응이 좋았다. 5년 회고의 「대작병」도 같다. 큰 게임은 혼자 끝나지 않았고 3일짜리 가벼운 게임이 다시 일어설 힘이 됐다.
- 68개, 30개 넘게 만든 끝에 대표작을 낸 1인 개발자, 한 달 출시·이틀 제작·3주 내부 테스트 사례가 반복된다.
- **기준** : 첫 게임은 한두 달 안에 끝나는 크기. 본업과 병행하는 1인이면 「한두 달에 하나」가 현실적이다 [추측].
- 출처 : ovov euni 「5년 동안 100개의 게임을 만든 인디개발사 Sokpop Collective」 https://youtu.be/tu4WoqnEMyc · 윤농 Yunnong 「5년 동안 혼자 게임 개발한 사람」 https://youtu.be/ET0xhdBRuEc

### 1-2. 기획 7단계 : 재미 먼저, 꾸밈은 나중(사례 4)
| 단계 | 할 일 |
|---|---|
| ① 핵심 컨셉 | 「어떤 재미를 줄까」를 한 문장으로. 모든 결정의 기준 |
| ② 제약 조건 | 예산·기간·인원·투입 시간. 아이디어가 커지는 것을 막는 울타리 |
| ③ 뾰족한 재미 | 플레이어가 반복해서 찾게 되는 1차 재미 하나 |
| ④ 구체화 | 레벨·인물·세계관을 그 재미에 맞춰 조립 |
| ⑤ POC | 그림 없이 **네모 상자·도형·카메라·소리·판정**만으로 재미 확인 |
| ⑥ 재조정 | 과감히 뺀다. **뺀 것과 이유를 기록**(개발일지 소재) |
| ⑦ 프로덕션 | 새 아이디어를 붙이지 않고 검증된 기획을 구현 |

- 1인은 제약 조건표(인원·본업 병행·엔진·도구의 상업 이용 여부·장비·출시 순서)를 한 번 적고 게임마다 「기간」만 새로 적는다.
- 「재미 한 줄」은 AI 지시문 맨 위에도 둔다. 기능이 마구 붙는 것을 막는다.
- 시제품에서 컨셉의 구조적 결함이 드러난 사례(위아래 층이 서로를 못 보는 층간소음 대결)가 있다. 회색 상자로 크기·카메라 판단이 어려우면 코드로 임시 그림을 붙인다.
- 출처 : Bawky 「게임을 기획할 때 꼭 필요한 7단계 과정!」 https://youtu.be/UxE7nesuvUM

### 1-3. 리믹스 : 되는 게임 + 내 소재(사례 6)
- 지도 퀴즈 → 스포츠판, 감염 확산 시뮬레이션 → 좀비처럼 **이미 되는 구조에 자기 분야를 얹는** 방식이 통했다. 잘 아는 분야(취미·직업·공부한 용어)면 단순한 형식으로도 차별점이 생긴다 [추측].
- 경계선 : 장르·플레이 방식은 자유, 이름·캐릭터·그림·소리·화면 구성은 새로(11절).
- **참고 게임 하나를 먼저 고정한다.** 참고 게임이 도중에 바뀌고 조작이 세 번 바뀐 시제품은 「어느 게임인지 모르겠다」로 끝났다. 저자는 「구현은 빨리 나왔지만 고르는 기준이 없었다」고 정리했다.
- 출처 : AI 사업일지 「코딩 모르는 비개발자가 이틀 만에 만든 게임, 월 4만 달러 앱이 되기까지」 https://youtu.be/TWOAq2zspKY · 아그나르(지피터스) 「고도(Godot)로 모바일 웹 게임 만들어 보자 : 클로드 코드 서브에이전트와 10시간」 https://www.gpters.org/dev/post/lets-create-highly-mobile-mghtHDehH19LYy2

### 1-4. 짧은 판과 다시 오게 하는 장치(사례 5)
- 「3분만 하는 게임」이 아니라 **「3분씩 여러 번 하는 게임」**. 판이 끝날 때마다 다음 판을 할 이유(해금·기록·수집)를 둔다.
- **하루 한 판 1분 + 결과 이모지 공유**(가입 없이 링크 하나)가 기술 부담이 가장 작은 형식이다. 단 재방문이 숙제였다.
- 밤에만 하루 한 마디씩 사연을 잇는 NPC, 레벨마다 배경·음악 교체, 오늘의 순위(8-4)도 다시 올 이유가 된다.
- 출처 : 웹핵 「광고비 0원으로 게임 유저 2400명을 모았습니다」 https://youtu.be/850D5F4ZtPc · AI-CLASS 「클로드 고급기능 활용하여 1위 모바일 게임 만드는 방법」 https://youtu.be/OcB99AdsjZI

### 1-5. 조작과 화면(사례 4)
- **세로 모바일 + 단순 조작**이 작은 게임과 잘 맞는다. 복잡하고 불친절한 조작은 컨셉이 좋아도 망한다. 출시 전 **처음 해 보는 사람의 첫 1분 시험**을 넣는다.
- 모바일 웹 + 홈 화면 설치 + 드래그는 검증되지 않은 경로다. 헤드리스 검사는 통과했지만 아이폰 웹앱에서 조이스틱 드래그가 끝내 안 됐다. 첫 게임은 **탭 위주**, 드래그가 필요하면 처음부터 네이티브 내보내기로 시험한다.
- 2D는 타격감 연출(화면 흔들림, 정지 프레임, 소리)을 직접 넣어야 한다.
- 출처 : 아그나르(지피터스)(위) · 윤농 Yunnong(위)

### 1-6. 이야기 설정을 규칙으로 바꾸기
- 목숨 공유 2인(대상이 살아 있으면 수호자는 안 죽고, 대상이 위험하면 잠깐 무적) → 호위에 동기와 보상이 생긴다. 무적에도 예외(재생 봉인, 재생보다 빠른 피해)를 둬 긴장을 유지한다.
- 수집 + 자원 소모 + 상성 : 소환마다 기력, 계약은 싸워서, 종류마다 약점. 주력 하나 + 상황기 여럿 구조가 된다.
- 출처 : 한 만화의 줄거리 소개 영상(구조만 가져옴, 링크 없음)

## 2. 엔진 고르기

### 2-1. 고도와 유니티
| 기준 | 고도(Godot) | 유니티 Personal |
|---|---|---|
| 라이선스 | **MIT, 완전 무료**, 로열티 0 | 연 매출+투자금 2억 9천만 원 미만 개인 무료(영상 값). 2023년 설치당 요금 논란처럼 약관이 바뀐 전례 |
| AI 궁합 | 씬·스크립트가 **텍스트 파일**(.tscn·.gd). AI가 직접 고치고 명령으로 실행·검사 | 공식 스킬 + 유니티 CLI + MCP |

| 주의 | 버전마다 문법이 바뀌어 **AI가 옛 문법을 자신 있게 쓴다** [추측] | AI 학습 자료가 많다 [추측] |

- 2D·소규모·웹/모바일이고 콘솔을 노리지 않으면 고도의 약점이 거의 걸리지 않는다. 판단 질문은 「프로젝트 파일이 메모장에서 읽히는가, 터미널로 실행·검사할 수 있는가」이다.
- 영상 한 편으로 정하지 말고 같은 작은 2D 게임을 두 엔진으로 하루씩 만들어, AI가 틀린 문법 횟수와 막힌 시간을 재서 정하는 방법이 있다.
- 출처 : MGD 「EP 3. 유니티, 언리얼 대신 왜 하필 고도??」 https://youtu.be/prAJhW3JjIk · 퍼니벅스의 게임 뉴스 「고도 엔진, 소규모 게임의 표준이 될 수 있을까?」 https://youtu.be/dG4Q3bFAPGA

### 2-2. 고도에서 유니티로 옮긴 사례
- 3D 1인칭 공포 게임에서 괴물 동작 하나에 나흘·시도 14번을 쓴 뒤 옮겼다. 이유는 **3D 뼈대 애니메이션과 연출 도구**였다.
- 엔진 탓이 아니었던 것 : 램프 빛 각도와 카메라 화각이 둘 다 80, 질감 연결 누락, 너무 옅은 안개. 같은 값이면 어느 엔진이든 같다.
- 이식 함정 : 두 엔진의 **앞 방향이 반대**라 갱도가 뒤집혔다. 검사는 못 잡고 눈이 잡았다. 옛 저장소는 지우지 않고 손으로 맞춘 값과 정리 문서만 가져갔다. 교훈은 「통역사(AI)가 아는 말로 시작하라」이다.
- 2D 시사점 : 결정적 이유는 작은 2D에 거의 해당하지 않는다. 다만 옛 문법 문제는 걸리므로 **고도 버전을 하나로 고정하고, 공식 문서를 함께 넣고, 실행 → 오류 → 수정 루프를 처음부터 건다.**
- 같은 채널의 앞선 실험(고도 3D, 코드로만, 하루·지시 8번)의 결론도 「모두 AI에 맡기기엔 아직 무리」였다.
- 출처 : 오완작 「Godot을 버리고 Unity로 간 이유」 https://youtu.be/r3T2vGR4OWU · 오완작 「Fable5.1 + Godot 엔진으로 지시만으로 어디까지 가능할까?」 https://youtu.be/b7FMhXhhnSg

## 3. 고도 입문과 함정

### 3-1. 시작 설정과 유니티 비교
- 프로젝트 설정 : 영문 경로, **호환성 렌더러**(웹용), 텍스처 필터 `Nearest`, 늘이기 모드는 픽셀 아트면 `viewport`·그 외 `canvas_items`.
- 캐릭터 원점은 발바닥. 중력은 계속 더하고 점프 속도는 한 번 대입, 점프는 `is_action_just_pressed`, 좌우 동시 입력은 멈춤, 왼쪽은 `flip_h`. 실행 중 값은 씬 탭 **원격(Remote)**.

| 고도 | 유니티 |
|---|---|
| 씬 하나가 프리팹·레벨 역할 | 프리팹과 씬이 따로 |
| 노드 종류가 곧 기능 | 빈 오브젝트 + 컴포넌트 |
| `@export` / 시그널 | `[SerializeField]` / UnityEvent |
| **y 아래가 +** | 2D에서 y 위가 + |
| `velocity` + `move_and_slide()` | Rigidbody2D |
| `get_tree().change_scene_to_file()` | `SceneManager.LoadScene()` |

- 출처 : Serene code 「Godot Engine 마리오라이크 2D PC 게임 만들기」(9편) https://youtube.com/playlist?list=PLHuCQsVXKUm8q0No9bFg_ZvL3JMG9SFzC

### 3-2. 2D 게임에 바로 쓸 구조
- **Tween** : 피격 번쩍임(`modulate`), 점수 카운트업(`tween_method`), HUD 슬라이드인. 변수에 보관하고 새로 만들기 전에 `kill()`.
- **적 AI는 `enum State` + `match`** : 진입·이탈 조건을 다르게(책은 1.5배) 줘서 경계에서 깜빡이지 않게.
- **탄막** : `Timer` → `instantiate()` → `add_sibling()` → `rotation = direction_to(player).angle()` → `position += transform.x * SPEED * delta`. 화면 밖 삭제를 반드시 넣는다.
- **체력·점수는 자동 로드 + 시그널**(`health_changed`를 HUD가 구독). 데이터는 `Resource` + `@export`(.tres)로 빼서 인스펙터에서 조정.
- **저장** : `FileAccess` + `JSON` + `user://`. 웹에서는 브라우저 저장소라 시크릿 창에서 사라질 수 있다 [추측].
- 출처 : 위키독스 「프로젝트로 입문하는 Godot 엔진」 https://wikidocs.net/book/18570 (안드로이드·웹 빌드 쪽은 비어 있고 포스트 프로세싱은 3D 한 쪽뿐이다. 책 코드에 오타가 있어 그대로 복사하지 않는다)

### 3-3. 고도 함정 모음
| 함정 | 대처 |
|---|---|
| 픽셀 아트가 흐림 | 기본 텍스처 필터 `Nearest` |

### 4-3. 유니티 기초 요점
- **이동 3원칙(2D에도 통함)** : `[SerializeField] private`, 대각선은 `.normalized`, 이동량에 `Time.deltaTime`.
- **그리는 순서** : Sorting Layer → Order in Layer. 나중에 끼우도록 10 간격.
- **스프라이트 자르기** : Multiple → Slice(Grid By Cell Size, 피벗 Bottom) → Apply → 프레임을 씬으로 끌면 애니메이션 생성.
- **Sprite Atlas** : 낱장 10개면 Batches 10, 아틀라스로 1. 방향 있는 셰이더 효과면 Allow Rotation 끄기, 외곽선이면 Padding 넉넉히, Variant(Scale 0.5·0.25)로 저사양판. **안드로이드는 처음부터 아틀라스로.**
- **그림 몇 장으로 생기 주기** : `Sprite[]`에서 `Random.Range`로 골라 `SpriteRenderer.sprite`에 넣는 4줄. **`OnEnable`에서 효과음 재생**(켜질 때마다 소리).

## 5. AI 에이전트·MCP로 게임 만들기

### 5-1. 작업 규칙 파일에 넣을 문구(사례 8)
`CLAUDE.md`·`AGENTS.md`처럼 AI가 가장 먼저 읽는 파일에 옮겨 쓴다.

```
1. 무엇을·왜·어떻게가 불분명하면 가정하지 말고 묻는다. 이해한 바를 먼저 말한다.
2. 구현 전에 문제점과 대안을 한 번 검토한다(매번 허락받을 필요는 없다).
3. 파일 여러 개를 한꺼번에 고쳐야 하면 먼저 확인받는다.
4. 한 파일에 다 넣지 말고 기능별로 모듈화한다.
5. 테스트 통과로 끝내지 않는다. 게임을 실행해 화면·동작을 캡처로 확인한다.
6. 같은 실수는 이 파일에 한 줄로 남기고, 쌓이면 합쳐서 줄인다.
```

- **고칠수록 불필요한 코드가 쌓인다** : 「그거 말고 이렇게」를 반복하면 잘못된 결과 위에 덧붙는다. git으로 되돌리고 다시 시킨다.
- **창 두 개 병렬** : 하나는 수정, 하나는 읽기 전용 검토(서브에이전트로 대신 가능).
- 출처 : MGD 「EP 9. AI로 게임 만들 때, 이 네 가지는 작업 규칙에 넣으세요」 https://youtu.be/PTWAzsvuUfI · 웹핵 「바이브 코딩으로 게임 출시하며 느낀점」 https://youtu.be/9Vrg3cNNdFM

### 5-2. 일하는 방식의 기본
- **계획 파일 먼저** : 첫 지시에서 `plan.md`에 구조·단계·도구 참고를 쓰게 하고 바뀔 때마다 갱신.
- **기능은 한 번에 하나씩**, 그때마다 실행한다.
- **AI가 엔진을 직접 실행해 오류를 읽게** : 고도 실행 파일 경로를 알려 주고 「직접 실행해 시험해」라고 하자 사람이 오류를 옮길 필요가 없어졌다.
- **에셋 목록(이름·크기·용도)을 먼저 받고 그 이름대로 그림을 만든다.** 「이미지는 모두 `images/`에」처럼 경로를 분명히.
- 막힌 화면은 캡처로, 말로 안 되는 그림은 거친 스케치로 보여 준다. 대화가 길면 compact, 지시는 구체적으로.
- **따라 하지 말 것** : `--dangerously-skip-permissions`(작업 폴더 허용으로 좁힌다), API 키를 대화창에 붙여 넣기(환경 변수·`.env`로만).

### 5-4. 자율 루프 : AI가 혼자 만들고 고치게 하기
루프 : ① 지시서 읽기 → ② 딱 하나 만들고 커밋 → ③ 세션이 끝나기 전에 한 일과 다음 할 일을 파일에 → 다시 ① 단계로.

| 기록 파일(그냥 마크다운) | 역할 |
|---|---|
| 기획서 | 무엇을 만드는가. 거의 안 고친다 |
| 인수인계서 | 어디까지 했고 다음은 무엇인가. **가장 중요** |
| 지시함(`INBOX.md` 등) | 사람이 한 줄씩. 다음 바퀴에 가장 먼저 처리 |
| 지시서 | AI가 매 바퀴 읽는 규칙과 QA 목록 |

**지시서 5원칙**
1. **품질 문장** : 「다른 사람이 봐도 퀄리티가 떨어지지 않는가? 걸리면 커밋하지 마라」. 품질을 가장 크게 바꾼 한 문장이다.
2. 바퀴마다 먼저 읽을 파일을 번호로 못박고, 어디까지 읽을지도 정한다.
3. **규칙마다 「왜」 한 줄** : 금지만 적으면 빠져나갈 길을 찾고, 이유를 적으면 이유를 지키려 한다.
4. 읽고 → 하나 만들고 → **직접 실행해 눈으로 확인** → 기록.
5. 검사를 통과하면 화면 확인 전에 일단 커밋한다.

- 시작 전 : git 필수, 격리된 폴더, 처음엔 두 바퀴만 수동으로. 터미널 밖(작업 스케줄러·cron)에서 띄우면 환경을 물려받지 않으니 **실행 파일은 절대 경로로**.
- 사람의 일은 기획서, 아이디어, 직접 해 보고 한마디. 피드백은 **「플레이해 보고 느낀 점 한 줄」**이면 충분하다(「주운 무기가 좋은지 판단이 안 된다」 → AI가 화면을 픽셀로 재고 등급별 바닥 발광을 넣었다).
- 화자 기록(검증 불가) : 24일에 커밋 1,428개, 그림 623장, 자동 검사 146개, 사람 코드 0줄.
- 출처 : Typical 30s 「AI가 혼자 게임을 만들고 수정하는 자율루프 세팅, 프롬프트 100% 공개합니다」 https://youtu.be/-0Yrj3SpH-U · Typical 30s 「바이브코딩도 귀찮은 직장인이 게임을 만드는 방법」 https://youtu.be/QWbM-NRTkEc

### 5-6. 고도 MCP 서버 고르기 [실측 : 2026-10-09]

- **MCP 없이도 된다** : 클로드 코드는 `godot --headless`로 실행하고 `.tscn`·`.gd`를 직접 고친다. MCP가 이기는 곳은 편집기를 연 채 실시간으로 바꾸고 보는 일이다.
- **설치 규칙** : 그 프로젝트 폴더에만(`--scope project`), 버전 고정, 고도 경로는 환경 변수로. 데스크톱 채팅 앱 설정은 전역이라 넣지 않는다. 설치 전 코드에서 외부 주소 호출을 찾아본다.

```
claude mcp add godot --scope project -e GODOT_PATH=<고도 실행 파일> -- cmd /c npx -y @coding-solo/godot-mcp@0.1.1
```

- **함정** [실측] : ① Git Bash에서 치면 `/c`가 `C:/`로 바뀐다 ② `-e`가 뒤 인자를 먹으니 서버 이름을 앞에 ③ `add_node`의 위치 값이 무시된다. 이 서버는 실행·출력 회수용으로, 씬 편집은 파일 수정으로. 프로젝트 범위 서버는 처음 열 때 사람이 승인해야 켜진다.

## 7. 이펙트·연출·애니메이션

### 7-1. 이펙트는 그림 대신 JSON 데이터로
- 사용자는 시각적 첫인상으로 할지 정한다. 캐릭터가 작고 폭발이 많은 장르면 이펙트만 잡아도 품질이 오른다.
- 노드 기반 이펙트 도구를 클로드로 만들었고 실체는 JSON이다. **AI에게는 이미지보다 구조화된 데이터가 성공률이 훨씬 높다.** 말로만 시키기보다 **「좋아하는 이펙트 JSON + 파란 검기로」**가 잘 맞는다.
- 확인 없이 내지 않게 렌더 → 프레임 확인 → 다시 렌더를 반복시킨다. MCP 없이 렌더 스크립트 + 프레임 캡처로도 된다.
- **기준 이펙트 하나에서 양을 늘린다.** 공개 웹 도구·커넥터는 외부 서버로 작업물을 보내니 체험용으로만 보고 자기 프로젝트 안에 만든다. 소재는 CC0·상업 이용 가능한 것만.
- 캐릭터 애니메이션은 일부러 최소(대기 1장·공격 6장)로 두고 나중에 한꺼번에 바꾼다. 공격 위계(일반 < 특기 < 스킬 < 궁극기)를 시각적으로 나누고 스킬 때 살짝 암전.
- 출처 : 용사주식회사 「이펙트 싹 갈았다! AI로 게임 VFX 만들기」 https://youtu.be/PqMle_luNX0

### 7-2. 2D 애니메이션 방식
| | 프레임(플립북) | 스켈레탈(뼈대) |
|---|---|---|
| 장점 | 쉽고 저사양에 강함, 아틀라스로 호출 감소 | 적은 그림으로 부드러움 |
| 단점 | 그림 수만큼 용량 증가 | 실시간 계산, 뼈·메시 최적화 필요 |

- 플레이어·보스는 스켈레탈, 작거나 많은 적·효과는 프레임으로 섞는다. 첫 안드로이드 게임은 작은 픽셀 + 프레임 위주 [추측].
- **유니티 2D Animation** : PSB 레이어 → 스키닝 에디터(메시·뼈·웨이트), **Sprite Library + Resolver**의 「카테고리 + 라벨」로 라이브러리만 바꿔 스킨 교체(셀 애니메이션에도), 2022 LTS부터 Aseprite 태그가 애니메이션으로. 스킨 교체는 한 게임 안의 다양성에 쓴다(두 게임이면 심사에서 「비슷하다」 위험).
- 파츠 애니메이션 원리 : 회전 중심은 관절, 파츠 이름 미리, 0초·1초 같은 자세 + 중간 엇갈린 자세 + 이징.
- 출처 : Unity Korea 「[2D 게임 개발 꿀팁] 2D 애니메이션」 https://youtu.be/lStxewSNxNA · Unity Korea(위) · DandyWing 「3D 렌더링을 스프라이트 변환」 https://youtu.be/ZnceSQ0dTlk

### 7-3. 「어색하다」를 숫자로 번역하기
- 3D 달리기를 18번 고친 기록이다. 발 미끄러짐 3mm 이하로 테스트는 통과했지만 사람 눈엔 어색했다. AI 보고서에 「정지 화면과 측정값만 봤고 연속 동작은 판정하지 않았다」는 단서가 있었다. **스스로 한계를 적는 보고 형식**이 좋다.
- 「운동하러 나온 사람 같다」를 AI가 상체 기울기·고개 방향·보폭 비율로 바꾸자 방향이 나왔다(기울기 약 20도 → 2~4도, 보폭 절반, 이동 속도는 그대로).
- **느낌 판정은 사람 몫, AI의 반대는 참고 의견** : AI가 반대한 무료 모션을 사람이 채택한 것이 전환점이었다.
- 점검 : 대기 모션이 따로 있는지(걷기를 섞으면 구부정), 재생 속도가 이동 속도에 맞는지(발 미끄러짐).
- 출처 : 나 혼자만 개발업 「테스트는 다 통과했는데, 어색했다」 https://youtu.be/oCnDRdXMZoU

## 11. 저작권 : BGM·폰트·IP·오마주(사례 8)

- **저작권은 만든 순간 자동으로 생기고**, 조금 고쳐도 바뀌지 않는다. 게임 아이디어 자체는 보호되지 않고 직접 만든 캐릭터·코드·일러스트·UI는 보호받는다.
- **조심할 세 가지** : ① **BGM** : 스트리밍 음악·게임 OST를 그대로 넣지 않는다. 「비상업용」이라고 무조건 허용되지 않는다 ② **폰트** : 무료 다운로드는 개인 사용만인 경우가 많고 무료 게임 배포도 상업적 사용으로 볼 수 있다. 구글 폰트 대부분은 OFL ③ **유명 IP 오마주** : 팬 게임도 배포하는 순간 경고장이 올 수 있고 「존중을 담은 오마주」는 법적으로 소용없다.
- **「무료」와 「상업 이용 가능」은 다르다.** 받을 때 라이선스 텍스트(또는 주소·날짜)를 저장하고 `LICENSES.md` 한 파일로 모은다 [추측 : 아이디어]. itch.io 에셋은 작가마다 조건이 다르다.
- **남의 그림을 입력으로 넣지 않는다** : 남의 캐릭터로 픽셀 캐릭터를 뽑거나, 이미지 검색·다른 게임 스크린샷을 잘라 쓰는 시연이 여러 영상에 있었다. 결과가 원본을 닮을 수 있으니 직접 만든 것이나 CC0 등 확인된 것만.
- **AI 생성물** : 판매 전 도구 약관과 판매처 정책 확인 [확인 못 함]. 고쳐도 워터마크(SynthID)가 남을 수 있으니 판매처 기준대로 AI 사용을 표기하고, 워터마크를 가리지 않는다.
- 게임 이름·화면에 남의 상표(게임 제목, 리그 로고)를 쓰지 않는다. 원본은 자기 PC에 보관하고 엔진은 MIT처럼 묶이지 않는 라이선스를 고른다. 개발일지에 옛 게임 화면을 쓸 때는 정식 구매본·공식 복각판·권리자 허락본만.
- 「무료」로 소개된 3D 에셋 팩(던전 팩·Quaternius)은 CC0로 알려져 있으나 [확인 못 함], 출시 전 원문을 확인한다.
- 출처 : 시디터 「이거 모르고 게임 출시하면 진짜 큰일남..(저작권 필수 내용 정리)」 https://youtu.be/lSgITspmguE (법률 자문이 아님) · Todaycoding(위) · 얕은생각(위)

## 12. 샘플 게임 기록 : 「별무리 사격」 [실측]

작성자가 클로드 코드로 만든 고전 고정 화면 슈팅 샘플이다. 플레이 방식만 빌리고 이름·그림·소리를 새로 만들었다.

- **사양** : 고도 4.7.2, 호환성 렌더러, 480×640 세로. 적 40기가 대열을 이루고 하나씩 고리를 돈 뒤 급강하, 급강하 중 격추 2배, 목숨 3, 재등장 2초 무적. 시작 전에 `CLAUDE.md`에 과제·지킬 선·확인 방법·끝나는 조건을 적었다.

| 적용한 교훈 | 방법 |
|---|---|
| 번역 가능하게 | 화면 문장 13개 전부 `i18n/strings.csv` + `tr()`, 한국어·영어 |
| 상태 유지 | `GameState` 자동 로드(점수·최고 점수·목숨·스테이지) |
| 그림·소리는 코드로 | 모두 `_draw()`(외부 그림 0장), `tools/make_sfx.py`가 사각파·잡음으로 효과음 6종(외부 음원 0개), 자동 로드 `Sfx`가 재생 |
| 봇 사용 검사 | `--autoplay`(조준·회피), `--nododge`(사망 경로), `[TEST]` 로그 |
| 실행 → 출력 회수 | `.mcp.json`, `run_project` → `get_debug_output` |

- **결과** : 헤드리스 자동 검사 에러 0, 봇 3분 스테이지 1~4 클리어, 회피 없는 봇으로 게임 오버 → 재시작 → 최고 점수 유지 확인, `--write-movie` 녹화에서 대열·한글·폭발 확인, 글꼴·효과음 추가 뒤 같은 시드 회귀 결과 동일.
- **고친 버그** : ① 타이틀에서 숨긴 기체를 `_process`가 매 프레임 다시 보이게 함 → `alive = false`(시각 검사로 발견) ② 정수 나눗셈 경고(MCP 출력으로 발견).
- **웹판** : 프리셋 `Web`, 스레드 끔. 한글 네모 상자는 Noto Sans KR Bold에서 141자만 남긴 부분집합(74KB, OFL)으로 해결.
- **함정** : MCP로 띄운 게임 창으로 사람이 다른 창에 치던 키가 들어가 「저절로 시작된」 것처럼 보였다. 창을 띄우는 시험은 옆 사람에게 알리거나 헤드리스로.
- 실행 : `<고도 실행 파일> --path <프로젝트 폴더>` (봇 관전은 ` -- --autoplay`, 편집기는 `-e`). 남은 일 : 사람이 하는 난이도·손맛 확인, itch.io 올리기.
