# 클로드 코드와 AI 도구 핵심 정리

유튜브 영상과 글 37편을 학습하며 정리한 내용을 주제별로 다시 묶은 요약본이다.
클로드 코드와 AI 도구를 처음 쓰는 사람부터 중급자까지, 바로 써먹을 명령·설정·조건·함정 위주로 남겼다.

- 근거 표시 : `[실측]` 작성자가 직접 확인, `[추측]` 추론, `[확인 못 함]` 원문 대조 전
- 영상의 수치·수익 사례는 화자의 발표 값이다. 따로 적지 않은 것은 재현하지 않았다.

## 1. 입문 : 용어·큰 그림

### 1-1. AI 용어 12개와 바로잡을 점

- LLM부터 멀티모달·RLHF·파인튜닝·RAG·MCP·에이전트·하네스·AGI까지 12개를 비유로 익힌다. 멀티모달은 똑똑해진 게 아니라 입력 종류가 늘어난 것이다.
- 바로잡을 점 ① RLHF는 반항을 억누르는 장치가 아니라 답을 사람 선호에 맞추는 학습이다. ② MCP가 없앤 것은 도구별 연동 작업이고 **승인은 남는다**. ③ RAG도 틀릴 수 있으니 출처를 붙여 대조한다. 자주 바뀌는 지식은 RAG, 말투·형식은 파인튜닝이 맞다 [추측 : 일반 지식].
- 출처 : 혼잡스 「모르면 따라가기 힘든 AI 용어정리 12개 딱 한 장으로 끝! (바이브코딩 지도 2부)」 https://youtu.be/N3st1ZrB_zc

### 1-2. 바이브 코딩 용어집

- 비개발자용 용어 70여 개를 11분류(프론트엔드·백엔드·DB·배포·Git·AI 코딩·명령어 `/init`·`/clear`·`/compact`·`/resume`·에러 등)로 정리한 사전이다.
- 주의 : AI 쪽 숫자(컨텍스트 200K 등)는 빨리 바뀐다. 클로드 코드가 고친 파일은 체크포인트나 Git으로 되돌린다 `[추측]`. 포트 사용 중(EADDRINUSE)은 띄우기 전 포트 확인으로 막는다.
- 출처 : 지피터스 「바이브 코딩 필수 용어집」 https://glossary.gpters.org/

### 1-3. 바이브 코딩 학습 순서

- 환경(IDE + Claude Code 또는 Cursor) → 형태(웹·앱·하이브리드) → 주제 → 화면부터 기획 → 화면 값으로 테이블 설계 → 클라이언트/백엔드 → 배포 순서다. 이미지는 DB가 아니라 파일 저장소에 둔다.
- 핵심 조언은 「HTML 한 장이라도 서버에 끝까지 올려 한 사이클을 먼저 돌린다」이다. 비용·보안은 다루지 않으니 배포 전 비밀키가 코드에 없는지 따로 본다.
- 출처 : 기술노트with 알렉 「바이브코딩 환경 설정 - 서비스 유형 - 주제 - 프론트엔드 - 백엔드 - 데이터베이스 - 서버 - 배포」 https://www.youtube.com/watch?v=CcEBaDXgjq0

### 1-4. 클로드 기능을 「언제 무엇을 쓰나」로 구분하기

| 기능 | 언제 쓰나 |
|---|---|
| 채팅 | 빠른 질문, 파일 하나 분석 |
| 프로젝트 | 같은 자료·배경을 매번 설명하고 있을 때 |
| 아티팩트 | 결과물을 옆에 띄워 보며 고칠 때 |
| 코워크 | 여러 작업을 이어 문서 업무를 끝까지 |
| 클로드 코드 | 폴더·파일 기반으로 더 깊게, 프로그램까지 |
| 스킬 | 같은 작성 방법을 매번 설명하고 있을 때(여러 곳에서 재사용) |
| 커넥터·MCP | 자료를 옮기는 사람이 나일 때 |

- 핵심은 「답이 아니라 결과를 요청한다」(「PDF 요약」이 아니라 「회의용 보고서까지」)와, 결과 뒤에 「원본과 비교해서 검증해 줘」를 붙이는 습관이다. 숫자·날짜·금액은 사람이 확인한다.
- 출처 : 해피AI 이진규 「2026 클로드(Claude) 올인원 무료 강의 — AI 업무자동화 20분 총정리」 https://youtu.be/58YFu8s2I8w

## 2. 클로드 코드 기본기

### 2-1. 탐색 → 계획 → 실행 → 커밋

- 파일을 먼저 읽히고 계획을 받아 빼고 더한 뒤 「방금 세운 계획대로」 구현하고 커밋한다. 시안은 **한 대화에서 연달아 시키면 앞 시안을 닮으니** `/branch`로 갈래를 나눈다 [확인 못 함 : 동작].
- 「하나만 완성 → 그 규칙을 스킬로 저장 → 나머지 확장」, 무거운 화면 작업은 서브에이전트에게 넘긴다.
- 출처 : AI 코딩밸리 「'진짜' 클로드 코드 사용법 — 기업에서 유용한 5개 프로젝트 완성」 https://youtu.be/bWPXADZylm0

### 2-2. AI에게 결정을 먼저 묻게 하기

- PRD 뒤 「결정이 필요한 사안을 먼저 물어봐」, 기술은 **한 번에 하나씩** 단점까지 듣고 고른다. 비개발자용 주석·리뷰 가이드를 받고, 오류는 「증상·조건·원인·해결」로 요청한다.
- 판매 서비스 점검 : 가격은 서버에서 재계산, 다운로드는 만료형 서명 주소, DB 변경은 마이그레이션 SQL, 운영 반영은 사람 승인, 결제·인증은 외부 서비스로.
- 함정 : 검증된 것은 데모 모드뿐이다. 환불 정책 등 법이 걸린 부분은 AI 검색 결과를 그대로 쓰지 말고 직접 확인한다.
- 출처 : 양실장의 바이브코딩대학 「3시간 순삭) 55개 기술 의사결정, 소스코드 해설까지!」 https://youtu.be/K6Rsy-pHBi0

### 2-3. 「검토표」 패턴 : 만들기 전에 상황부터 묻기

- 프롬프트에 「코드 전에 검토표(상황 질문지)를 먼저 만들라」를 넣고, 체크 결과를 「결정」으로 다시 넘기면 맞춤 도구가 나온다. 시연 도구(시간 기록기·회의 타이머 등)는 한 장짜리라 직접 만드는 편이 빠르다.
- 공개 프롬프트는 라이선스 표시가 없어 그대로 쓰지 않는다. 패턴만 배우고 도구는 직접 만든다.
- 출처 : 김지백(모두의 AI 교육) 「시간관리 AI 도구 9개, 전부 무료로 드립니다｜로그인·유료 전환 없음 + 우리 회사 맞춤 제작법」 https://youtu.be/_kGlA7axtvY

### 2-4. 디자인의 「AI 티」를 줄이는 순서

- 기획 문서 → **흑백 스케치**(문장과 순서만 고침) → 디자인 스킬로 초안 2개 → 구역별로 덜어내고 채우는 마감 → 모바일 점검. 초안은 「덜 고쳐도 되는 것」을 고른다.
- 스킬 [실측 : GitHub] : `pbakaus/impeccable` Apache 2.0, `Leonxlnx/taste-skill` MIT로 상업 이용 가능하다. 명암비·이미지 저작권은 다루지 않았다.
- 출처 : 인디해커 라이프(Jay Choi) 「클로드 코드 디자인, 이 순서대로만 하면 AI 티가 사라집니다」 https://youtu.be/2-Hg8BXcckc

### 2-5. `/doctor`로 정리할 네 가지

- ① 안 쓰는 스킬·MCP의 컨텍스트 차지량을 보고 끈다 ② 코드만 봐도 아는 것은 `CLAUDE.md`에서 뺀다 ③ 옛 모델 기준 지시를 「프롬프트 점검」으로 고친다 ④ 부딪히는 지시는 하나만 남긴다.
- 「주의할 점」과 「정한 이유」는 지우지 않는다. 지우기 전에 끄기부터 하고, 터미널의 `claude`에서 돌린다.
- 출처 : 마일드코드 「클로드 코드, /doctor로 정리할 4가지」 https://youtube.com/shorts/qq_KZMwPw2Q

### 2-6. 코덱스·클로드 코드·안티그래비티를 한 환경에

- 세 도구를 깔고 `Agy`·`claude`·`codex`로 로그인한다. 자주 쓰는 명령은 `/model`, `/usage`·`/status`, `/compact`, `/clear`다. 같은 지시에도 결과가 달라, **엔진과 독립된 하네스**로 기준을 고정해야 한다.
- 함정 : 영상은 승인 건너뛰기 모드를 일상적으로 쓰고 설치 출처도 에이전트에게 맡긴다. 무승인 실행은 격리된 폴더에서만, 설치는 공식 출처 확인 뒤 하나씩 한다. 구독료는 겹친다.
- 출처 : CNV AI 「AI 에이전트 만들기 1단계 | Codex·Claude·Gemini를 하나의 환경에서 쓰는 법」 https://youtu.be/bSpwsDM5pqo

## 3. 하네스·검증·자율 작업

### 3-1. 하네스 엔지니어링의 세 기둥

- 모델이 아닌 것은 모두 하네스다(`CLAUDE.md`·MCP·스킬·훅). 실수하면 프롬프트가 아니라 **구조를 고쳐 반복되지 않게** 한다. 「프롬프트는 부탁, 하네스는 강제」다.
- ① 컨텍스트 파일은 지도처럼 짧게(약 60줄 [확인 못 함 : 근거]), 실패할 때마다 「왜」를 붙인 한 줄 ② 자동 강제(린터·훅·권한 차단), 「성공은 조용히, 실패만 시끄럽게」 ③ 가비지 컬렉션(문서와 실제가 어긋난 곳 청소).
- 바로잡을 점 : 깃 커밋 전 훅과 Claude Code 훅(이벤트별)은 다르다. `CLAUDE.md`도 결국 프롬프트라 강제력은 훅·권한에 있다. 모델이 좋아지면 옛 규칙을 지울 수 있는지 본다.
- 출처 : 아는개발자 「하네스 공식문서 100번 읽은 것처럼 만들어드림」 https://youtu.be/DrekqeDlO1w

### 3-2. 두 AI 팀 교차 검증(Orca)

- `stablyai/orca`(MIT)는 에이전트마다 Git 작업 트리를 주는 작업장이다. 근거 수집 → 팀별 독립 판단 → 교차 반박 → **코드로 출처·수치 검산** → 취합 → 대시보드, 결정은 사람이 한다. 같은 작업을 두 팀에 똑같이 줘야 모델 차이만 비교된다.
- `CLAUDE.md`와 `AGENTS.md`는 심볼릭 링크로 한 파일로 묶고, 결과는 사람용 `.md`와 다음 단계용 `.json`으로 같이 낸다.
- 함정 : 같은 입력을 쓰면 입력 오류는 양쪽에 똑같이 들어가니 제3 출처를 붙인다. 약 4시간 반에 사용량 95%를 썼으니 반박은 충돌할 때만 돌린다. Codex 쪽은 유료 구독이 필요하다.
- 출처 : 후츠릿 「Claude팀 vs Codex팀이 매긴 목표가 | Orca 교차검증 시스템」 https://youtu.be/ASnanWMEPsI

### 3-3. 자는 동안 맡기는 일

- 결과를 스스로 확인할 수 있는 일만 맡긴다 : 테스트 채우기(통과한 것만 커밋), 버그(재현 테스트 → 수정 → PR), 시제품, 디자인 → 코드. **끝나는 조건과 횟수·시간 상한을 반드시 걸고**, 아침 검토는 필수다.
- 다운로드·공개 발행·결제가 끼는 일은 사람 승인 없이 지나가므로 넣지 않는다.
- 출처 : Solostack 「자는 동안 AI가 12시간 혼자 일하게 하는 법 (실전 4가지)」 https://youtu.be/J9fl07uHjXs

### 3-4. 검증과 위임에 바로 옮길 규칙(외부 스킬 18종에서 추림)

- 슈퍼파워즈(`obra/superpowers`) 15종, grill-me, karpathy-guidelines, agent-browser를 두 모델이 따로 검토해 **둘 다 꼽은 규칙만** 남겼다. 상세 검토는 4-3을 본다.

| 규칙 | 출처 스킬 |
|---|---|
| 증거는 이번에 새로 실행한 결과만. 린터 통과 ≠ 빌드 성공 | verification-before-completion |
| 기대값은 손으로 확인한 리터럴, 끝내기 전 전체 스위트 | test-driven-development |
| 승인은 그때 보여 준 단계에만 유효 | brainstorming |
| sleep을 늘리지 말고 조건이 될 때까지 폴링 | systematic-debugging |
| 하위 에이전트 호출 때 모델을 늘 명시(생략하면 비싼 모델 상속) | subagent-driven-development |
| 리뷰 지적이 불명확하면 전부 보류하고 먼저 묻는다 | receiving-code-review |
| 이번 변경으로 안 쓰이게 된 것만 지운다 | karpathy-guidelines |
| 스킬 description에는 언제 쓰는지만 쓴다 | writing-skills |

## 4. 스킬·MCP·모드(Mods)

### 4-1. MCP 붙이는 법과 고르는 기준

- 연결은 `claude mcp add <이름> <주소>`(주소 방식은 `--transport http`), 확인은 `/mcp`, `--scope user`면 모든 프로젝트에서 쓴다.

### 4-5. 클로드 코드 모드(Mods)의 구조

- 2.1.287부터의 기능이다. 훅이 바깥에서 셸 명령을 돌린다면, 모드는 타입스크립트로 **안에서** 돌며 화면을 다시 그리고 도구 호출에 끼어든다. 추가 비용은 없다.
- 구조 [실측 : 공식 타입 정의] : `hooks/hooks.json`의 `{ "modules": ["./register.tsx"] }`, `on(event, matcher?, hook)`(`prompt.submit`·`tool.call`·`ui.render`), 처리기 `($, e, next)`에서 `next(e)`면 기존 동작이다. 자리는 `AbovePrompt`·`Pane`·`AssistantMessage` 등이고 입력창만 못 건드린다. 픽셀 그림은 터미널 전용이다.

### 4-6. 모드 직접 만들기와 함정

- ① `claude --version` 2.1.287 이상 ② 「어느 자리 / 무엇을·어디서 값을 / 끝난 모양 / 대비책」 4요소로 요청 ③ 핫 리로딩은 **「이번 세션에서 활성화」** ④ 자리를 바꿔 덧붙임 ⑤ 다른 세션은 `claude --plugin-dir`이나 마켓플레이스. 검증은 `claude plugin validate`·`claude plugin test`.
- 택시 팩(MIT) [실측] : meter(API 정가 환산 요금, 실제 청구액 아님)·blackbox·speedcam·navi, 외부 통신 없음. 설치 순서가 실행 순서라 blackbox를 먼저 깐다.
- 함정 [실측 : 작성자가 가림 모드를 만듦] : 밴드에서 `next(e)`를 안 부르면 **다른 모드의 띠를 덮어쓴다**. 상태 계약 파일에 `export {}`를 쓰지 않는다. Git Bash 히어독은 정규식 백슬래시를 줄인다.

```bash
claude plugin marketplace add devbrother2024/devbrothers-mods
claude plugin install taxi-meter@devbrothers-mods
```

## 6. 지식 관리 : LLM 위키, 노트북LM

### 6-1. LLM 위키의 구조

- RAG는 질문마다 조각을 조립하고 버리고, LLM 위키는 자료가 들어올 때 미리 읽어 쌓는다(카파시 제안). RAG의 빈틈은 **두 문서가 어긋난다는 사실이 기록되지 않는 것**이다.
- 세 층 : raw(원본, 읽기만) · wiki(LLM이 쓰는 마크다운) · schema(`CLAUDE.md` : 주장마다 출처·시점, 상충 표시, 출처 신뢰 순위). **품질은 schema가 정한다.** 동작은 ingest·query(좋은 답은 「저장해 줘」)·lint다. 옵시디언 터미널 플러그인에서 클로드 코드를 띄워 실습한다.
- 한계 : 토큰 비용, 수천 쪽이면 다시 검색 필요(RAG와 보완), 쌓인 환각을 더 믿게 된다.
- 출처 : 6-2와 같다.

### 6-2. 자동 위키 하네스 원칙

- **판단은 에이전트, 검산은 코드.** 에이전트 답은 JSON으로 받아 코드가 재검사한다. 검사 에이전트에게는 쓰기 도구를 아예 주지 않는다. 작업 공간(`_build`)과 서빙 공간을 나누고 게이트 기본값은 차단이다.
- ★검사 에이전트가 판정 없이 조용히 멈춘 사례가 있었다. **「확인 불가도 실패」, 「판정 누락이면 재호출」**로 고친다. 문서는 초안 → 안정 → 폐기로 표시하고, 어긋나는 문서는 「상충」으로 남긴다.

### 6-3. NotebookLM으로 기획, 안티그래비티로 구현

- 고른 자료만 넣고 「소스 안에서만 답하라」로 아이디어를 받은 뒤, 목적·기능·흐름이 담긴 **지시문을 먼저 파일로 뽑아** 코딩 도구에 넘긴다. 안 되는 점은 불만을 구체적으로 적어 보낸다.

### 7-1. 코랩 LoRA 학습 → GGUF → 로컬 실행

- 코랩 무료 GPU에서 Gemma 계열 소형 모델을 LoRA로 학습 → 허깅페이스 → GGUF 변환 → LM Studio로 로컬 실행한다. 학습은 코랩, 실행은 로컬로 나누는 분업이다.
- 함정 : 학습은 구글 서버에서 하고 허깅페이스는 **기본 공개**라 개인 정보를 넣지 않는다. 토큰은 Full access 대신 쓰기·저장소 하나로 제한한다. 9건 데이터는 과적합이 났다. Gemma는 구글 자체 약관이고 [확인 못 함], 올라마(MIT)도 대안이다.
- 출처 : CONNECT AI LAB 「빌려 쓰는 AI 말고, 소유하는 AI」 https://youtu.be/uqoOL4kCxXw

## 9. AI로 돈 버는 법 : 현실적인 정리

### 9-1. 「누가 왜 돈을 내나」로 등급 매기기

- 누구나 대량으로 만드는 것은 낮은 등급, 고객 문제를 결과로 풀고 유지보수 매출이 붙는 일은 높은 등급이다. **누군가 돈을 내고 싶은 결과물**을 만들고, 작은 첫 결제를 첫 확인으로 삼는다. 수익 주장은 증빙이 없고 「월 50만 원」은 가정 계산이다.
- 출처 : 잭피디의 바이브코딩 아카데미 「클로드로 자면서 월 100만원 더 수익내는 ai 부업 티어리스트 (직접해봤습니다)」 https://youtu.be/x6lcK-7q0T8

### 9-2. 다섯 가지 수익 경로와 근거 수준

|---|---|---|
| 리서치 대행(크몽·파이버) | 시간 없는 사장님. 한 분야로 좁혀 「전문」으로 | 화자 관찰 |

## 10. 공통 교훈

1. **비밀값은 채팅에 넣지 않는다.** 키는 터미널이나 `.env`로 넘기고 저장소에는 `.env.example`만 올린다.
2. **사람 확인은 비가역 작업 바로 앞에.** 결제·비밀번호·공개 발행·차단 우회는 사람이 하고, 무승인 모드는 격리된 폴더에서만 쓴다.
3. **판단은 AI, 검산은 코드.** 기계로 확인할 수 있는 것은 코드로 재검사하고 「확인 불가」·「판정 누락」은 실패로 센다.
4. **같은 입력은 같은 오류를 낳는다.** 교차 검증에도 제3 출처를 붙이고, 자기 채점 확률은 믿지 않는다.
5. **권한은 도구·설정으로 나눈다.** 검사 담당은 읽기 도구만, 위험 명령은 훅·권한 차단으로 막는다.
6. **적게 붙이고 자주 정리한다.** MCP·스킬은 매일 쓰는 것만, 지우기 전에 끄기부터, 규칙마다 「왜」 한 줄.
7. **쪼개고 하나씩 결정한다.** 결정 사안을 먼저 묻게 하고 완료 기준을 준다.
8. **무료·라이선스는 원문으로.** 카드 등록·비상업 조항·휴면 정지를 상업 이용 전에 보고, 설치 전 저장소 코드를 훑는다.
9. **만드는 것과 버는 것은 다르다.** 「누가 왜 돈을 내나」를 첫 줄에 쓴다.
10. **외부 서비스에 자료를 넣기 전 보안 규정을 본다.** 위험이 낮은 개인 자료부터 시작한다.
