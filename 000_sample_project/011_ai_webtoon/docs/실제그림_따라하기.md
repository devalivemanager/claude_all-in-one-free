# 실제 그림으로 웹툰 1화 완성하기 — 따라 하기

코드 그림 콘티로 이야기와 연출을 확정한 뒤, 이미지 AI 그림으로 바꿔 끼워 「진짜 웹툰처럼 보이는」 1화를 만드는 절차입니다.
예제 회차 `episodes/ep01.json`(「금요일 오후 6시의 1원」, 컷 6개, 인물 3명)으로 설명합니다.

```
1 이야기 확정 → 2 프롬프트 뽑기 → 3 캐릭터 기준 그림 → 4 컷 그림 받기
→ 5 컷마다 점검 → 6 파일 정리 → 7 조립 → 8 화면 검수 → 9 공개 전 확인
```

> 핵심 원칙 세 가지
> 1. **그림은 마지막에.** 이야기를 바꾸면 그림을 다시 받아야 한다. 대본과 콘티를 먼저 끝낸다.
> 2. **글자는 그리지 않는다.** 이미지 AI 는 한글을 자주 틀리게 그린다. 대사·자막은 이 도구가 그림 위에 코드로 얹는다.
> 3. **같은 사람으로 보이게.** 캐릭터 기준 그림을 먼저 만들고, 모든 컷에 참조 이미지로 함께 넣는다.

## 준비물

| 무엇 | 설명 |
|---|---|
| 이 폴더 | Node.js 22 이상. `npm test` 가 통과하는지 먼저 본다 |
| 이미지 AI 하나 | 채팅형 이미지 생성(예: ChatGPT 이미지), 미드저니, PC 의 Stable Diffusion 등. **상업 이용 조건을 먼저 읽는다** |
| PNG 로 보기(선택) | `--png` 를 쓰려면 Playwright(Chromium). 없으면 `index.html` 을 브라우저로 연다 |

## 1단계. 이야기를 확정한다 (그림 없이)

```bash
cd 000_sample_project/011_ai_webtoon
node src/cli.mjs episodes/ep01.json -o output/ep01 --png
```

- 마지막 줄이 `컷 6개, 말풍선 8개, 경고 0건, webtoon.png 저장` 이어야 한다. 경고가 있으면 대본을 먼저 고친다.
- `output/ep01/storyboard.md`(콘티 표)와 `webtoon.png`(코드 그림 콘티)를 보며 확인한다.
  - 대사가 자연스러운가, 반전이 다음 컷에서 보이는가, 마지막 컷이 다음 화를 궁금하게 하는가
  - 컷 사이 여백(`gap_after`)이 호흡에 맞는가 (README 「연출 규칙」)
- 새 회차를 처음부터 만들 때는 클로드 코드에서 「웹툰 2화 기획해 줘」라고 하면 스킬 `webtoon-planner` 가 대본 JSON 을 만든다.

**여기서 이야기를 끝낸다.** 다음 단계부터는 그림 작업이다.

## 2단계. 이미지 프롬프트를 뽑는다

```bash
node src/cli.mjs episodes/ep01.json -o output/ep01 --prompt-lang en
```

미드저니처럼 영어가 잘 맞는 도구는 `--prompt-lang en`, 한국어를 잘 알아듣는 채팅형 도구는 빼도 된다.
`output/ep01/prompts.md` 는 두 부분으로 나뉜다.

1. **캐릭터 기준 그림** — 인물마다 하나. 비율 2:3, 파일 이름 `ref_<인물 id>.png`
2. **컷 그림** — 컷마다 하나. 비율, 크기, 파일 이름이 프롬프트 위에 적혀 있다

예제 회차의 컷 그림 목록(실제 출력):

| 컷 | 비율 | 크기 | 말풍선 자리 |
|---|---|---|---|
| p1 | 3:2 | 720×480 | 위쪽 49% |
| p2 | 4:3 | 720×520 | 위쪽 49% |
| p3 | 16:9 | 720×400 | 없음(대사 없는 모니터 컷) |
| p4 | 3:2 | 720×480 | 위쪽 49% |
| p5 | 5:4 | 720×600 | 위쪽 49% |
| p6 | 5:4 | 720×560 | 위쪽 49% |

- **비율**: 이미지 AI 는 대개 픽셀 크기 대신 3:2, 4:3 같은 비율을 받는다. 도구가 그 비율을 고를 수 없으면 가장 가까운 것을 고른다. 조금 달라도 조립할 때 가운데를 기준으로 잘라 맞춘다.
- **말풍선 자리**: 대사가 있는 컷의 프롬프트에는 「위쪽 49% 는 단순한 배경으로 비워 두고, 머리 꼭대기는 그 아래에」라는 줄이 들어 있다. 이 도구가 말풍선을 놓는 범위와 같은 계산에서 나온 숫자다. 이 줄이 없으면 말풍선이 얼굴이나 중요한 소품을 가린다.
- 컷 프롬프트마다 인물의 외모 설명이 **글자 하나 다르지 않게** 반복된다. 일부러 그런 것이니 줄이지 않는다.

## 3단계. 캐릭터 기준 그림을 만든다

컷마다 같은 사람으로 보이게 하는 가장 중요한 단계다.

1. `prompts.md` 의 「1) 캐릭터 기준 그림」에서 인물 하나의 프롬프트를 복사해 이미지 AI 에 넣는다. 비율은 2:3.
2. 3~4장을 받아 가장 나은 것 1장을 고른다. 외모 설명을 **항목별로** 대조한다.
   - 예: 한나 = 20대 여성 / 짧은 갈색 단발 / 둥근 안경 / 파란 셔츠
   - 하나라도 다르면 다시 받는다. 여기서 틀린 것은 모든 컷에 퍼진다.
3. 고른 그림을 `art/ep01/refs/ref_hana.png` 로 저장한다.
4. 인물 수만큼(예제는 hana, doyun, miso 3명) 반복한다.

같은 그림체로 맞추려면, 두 번째 인물부터는 첫 인물의 기준 그림도 함께 넣고 「같은 그림체로」라고 덧붙인다.

## 4단계. 컷 그림을 받는다

컷 하나씩 아래를 반복한다. **p1 부터 하나씩 확인하며 진행한다.** 6컷을 한꺼번에 받으면 같은 실수가 6번 반복된다.

1. `prompts.md` 의 「2) 컷 그림」에서 그 컷의 프롬프트를 복사한다.
2. 그 컷에 나오는 인물의 기준 그림(`ref_*.png`)을 **참조 이미지로 함께 넣는다.**
3. 비율을 그 컷의 비율로 정한다.
4. 3~4장을 받아 5단계 점검표로 고른다.

도구별로 하는 방법 (기능 이름은 버전마다 바뀌므로 쓰는 도구의 도움말에서 확인한다):

| 도구 종류 | 참조 이미지 넣기 | 비율 정하기 | 같은 사람 유지 팁 |
|---|---|---|---|
| 채팅형 이미지 AI | 기준 그림을 대화에 올리고 「이 그림의 인물과 같은 사람으로」 + 프롬프트 | 프롬프트의 「aspect ratio 3:2」 문장, 또는 도구의 비율 선택 | 한 대화 안에서 컷을 이어서 받으면 그림체가 덜 흔들린다 |
| 미드저니 | 이미지 참조 기능(캐릭터·스타일 참조)에 기준 그림 주소 | 비율 옵션(예: `--ar 3:2`) | 마음에 든 결과의 시드·스타일 값을 다음 컷에도 쓴다 |
| PC 의 Stable Diffusion | 참조 이미지 확장(IP-Adapter 등) | 해상도를 직접 지정(예: 3:2 → 1080×720) | 같은 모델·시드·설정을 컷 사이에 유지한다 |

## 5단계. 컷마다 점검한다 (받은 그림을 고를 때)

| 점검 | 통과 기준 | 안 되면 |
|---|---|---|
| 글자 없음 | 간판·화면·종이에도 글자가 없다 | 다시 받는다. 프롬프트 끝의 「No text…」 줄이 빠지지 않았는지 본다 |
| 인물 수 | 프롬프트의 등장인물 수와 같다 | 다시 받는다 |
| 위치 | 「position: left/right」 대로 서 있다 | 다시 받거나, 8단계에서 대본의 `x` 를 그림에 맞춘다 |
| 같은 사람 | 머리 모양·안경·옷 색이 기준 그림과 같다 | 기준 그림을 참조로 넣었는지 확인하고 다시 받는다 |
| 말풍선 자리 | 위쪽(예제는 49%)이 단순한 배경이다 | 다시 받는다. 「인물을 더 아래에, 상반신만」을 덧붙여도 된다 |
| 표정 | 프롬프트의 expression 과 같다 | 다시 받는다 |

## 6단계. 파일을 정리한다

```
art/ep01/
├── refs/            # 캐릭터 기준 그림(조립에는 쓰지 않는다)
│   ├── ref_hana.png
│   ├── ref_doyun.png
│   └── ref_miso.png
├── p1.png
├── p2.png
├── p3.jpg           # PNG·JPEG·WebP 모두 된다
├── p4.png
├── p5.png
└── p6.png
```

- 파일 이름은 **컷 id 그대로**다. 확장자는 `.png` `.jpg` `.jpeg` `.webp` 중 하나, 같은 컷에 파일은 하나만.
- 파일 하나는 10MB 까지. 형식은 확장자가 아니라 파일 내용으로 확인한다.
- `art/` 는 `.gitignore` 에 들어 있어 커밋되지 않는다.

## 7단계. 조립한다

```bash
node src/cli.mjs episodes/ep01.json -o output/ep01 --images art/ep01 --png
```

- 마지막 줄이 `경고 0건` 이면 6컷 모두 그림이 들어간 것이다.
- 그림이 없는 컷은 코드 그림으로 대신하고 `경고: 컷 p6: … 그림 파일이 없습니다` 처럼 알려 준다. **그래서 일부 컷만 먼저 넣어 보며 진행해도 된다.**
- 결과: `output/ep01/index.html`(세로 스크롤 페이지), `output/ep01/webtoon.png`(전체 캡처). 맨 아래에 `그림: 그림 파일` 이 보인다.

## 8단계. 화면으로 검수한다

`webtoon.png` 를 위에서부터 내리며 본다. 클로드 코드에 「output/ep01/webtoon.png 를 이 점검표로 봐 줘」라고 맡겨도 된다.

| 보이는 문제 | 고치는 방법 |
|---|---|
| 말풍선 꼬리가 말하는 사람을 가리키지 않는다 | 대본에서 그 컷의 `cast[].x`(0~1, 인물 중심의 가로 위치)를 그림 속 인물 위치에 맞춘다. 예: 인물이 화면 왼쪽 1/4 에 있으면 `0.25` |
| 말풍선이 얼굴을 가린다 | 그 컷을 다시 받는다(인물을 더 아래에). 또는 대사를 줄여 말풍선을 작게 한다 |
| 컷마다 다른 사람처럼 보인다 | 기준 그림을 참조로 넣었는지 확인. 외모 설명(`desc`/`desc_en`)을 더 구체적으로(머리 길이, 안경 모양, 옷 색) 고치고 다시 받는다 |
| 그림체가 컷마다 다르다 | 같은 대화·같은 시드·같은 설정에서 받는다. `style`/`style_en` 을 더 구체적으로 쓴다 |
| 중요한 것이 잘려 나갔다 | 그 컷의 비율로 다시 받는다(가운데 기준으로 잘리므로 가장자리에 중요한 것을 두지 않는다) |

대본(`x`, 대사)을 고쳤다면 7단계를 다시 실행한다. 그림을 다시 받을 필요는 없다.

## 9단계. 공개 전에 확인한다

- [ ] 쓴 이미지 AI 의 이용 약관에서 상업 이용·게시 조건을 확인했다
- [ ] 특정 작가나 기존 웹툰의 화풍·캐릭터를 흉내 내지 않았다(대본 검증이 흔한 표현을 막지만 전부는 아니다)
- [ ] `art/`, `output/` 을 공개 저장소에 올리지 않았다
- [ ] 마지막으로 사람이 처음부터 끝까지 한 번 읽었다

## 자주 막히는 곳

- **그림에 글자가 계속 생긴다** — 도구에 따라 「No text」를 무시하기도 한다. 반대로 적는 칸(negative prompt)이 있으면 `text, letters, watermark, speech bubble` 을 넣는다.
- **비율을 고를 수 없다** — 가장 가까운 비율로 받는다. 조립할 때 가운데 기준으로 잘린다.
- **`경고: … 이미지 파일이 아닙니다`** — 확장자만 `.png` 인 다른 파일이다(예: 웹 페이지를 저장한 것). 이미지로 다시 저장한다.
- **`경고: … 여러 개입니다`** — `p1.png` 와 `p1.jpg` 가 함께 있다. 하나만 남긴다.
