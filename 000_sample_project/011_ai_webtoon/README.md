# 011_ai_webtoon — 대본으로 세로 스크롤 웹툰 만들기

회차 대본(JSON) 하나로 세로 스크롤 웹툰 페이지(`index.html`)를 만드는 교육용 CLI입니다.
그림은 기본적으로 **코드로 그린 캐릭터**(SVG)를 쓰고, 원하면 **이미지 생성 AI**를 연결할 수 있습니다.
어느 쪽이든 대사와 말풍선은 그림 위에 코드로 얹습니다.

> 예제 회차 「금요일 오후 6시의 1원」은 이 저장소를 위해 새로 쓴 오리지널 이야기입니다.
> 8장(`001_hr_payroll`)의 장기요양보험료 중간 절사(과세 대상액 1,000,050원 → 4,590원) 이야기를 이어받았습니다.

## 왜 이렇게 나눴나

| 일 | 맡는 쪽 | 이유 |
|---|---|---|
| 줄거리·콘티·대사 | 사람 + 클로드(스킬 `webtoon-planner`) | 글 작업은 클로드가 잘하고, 대본 JSON 으로 남기면 고치기 쉽다. 결과는 콘티 표(`storyboard.md`)로 검토한다 |
| 캐릭터 일관성 | 설정표(`characters`) | 코드 그림은 같은 설정표면 항상 같은 얼굴. 이미지 AI 에는 외모 설명(`desc`)을 매 컷 **글자 그대로** 넣는다 |
| 그림 | 코드(SVG) 또는 이미지 AI | 이미지 AI 는 바꿔 끼울 수 있게 어댑터로 분리 |
| 대사·말풍선 | 코드 | 이미지 AI 는 그림 속 한글을 자주 틀리게 그린다. 프롬프트에 「글자·말풍선 넣지 않기」를 항상 붙인다 |

## 기술 스택

- Node.js 22 (외부 의존성 없음)
- 테스트: `node:test` 81개 (브라우저 테스트 2개는 Playwright 가 있을 때만)
- PNG 저장(`--png`)과 브라우저 테스트: Playwright (전역 설치본 사용, 없으면 해당 기능만 안내 후 건너뜀)

## 폴더 구조

```
011_ai_webtoon/
├── .claude/skills/webtoon-planner/SKILL.md  # 시놉시스 → 대본 JSON 기획 스킬
├── episodes/ep01.json   # 예제 회차 대본(컷 6개, 말풍선 8개, 영어 프롬프트 필드 포함)
├── src/
│   ├── cli.mjs          # 실행 진입점
│   ├── script.mjs       # 대본 읽기·검증(오류를 경로와 함께 한 번에 모아 알림)
│   ├── text.mjs         # 한글 글자 폭 추정·줄 나누기
│   ├── layout.mjs       # 말풍선 배치(화자 위, 읽는 순서, 겹침 없음)
│   ├── characters.mjs   # 설정표로 캐릭터·배경 그리기
│   ├── prompt.mjs       # 컷별 이미지 AI 프롬프트(비율·말풍선 자리), 캐릭터 기준 그림 프롬프트
│   ├── painters.mjs     # 그림 도구: svg(기본) / api(이미지 AI) / files(그림 파일 폴더)
│   ├── render.mjs       # 컷 SVG·회차 HTML 만들기
│   └── browser.mjs      # Playwright 불러오기
├── docs/실제그림_따라하기.md  # 이미지 AI 그림으로 1화 완성하는 단계별 안내
└── tests/               # 단위·CLI·브라우저 테스트
```

## 실행 방법

```bash
cd 000_sample_project/011_ai_webtoon
npm run build          # output/ep01/index.html, prompts.md
npm run build:png      # 위 + output/ep01/webtoon.png (Playwright 필요)

# 직접 실행
node src/cli.mjs episodes/ep01.json -o output/ep01 [--png] [--painter svg|api] [--images 그림폴더] [--prompt-lang ko|en]
```

출력 예시:

```
완료: .../output/ep01/index.html
컷 6개, 말풍선 8개, 경고 0건, webtoon.png 저장
```

| 파일 | 내용 |
|---|---|
| `index.html` | 세로 스크롤 웹툰. 컷마다 장면 설명이 대체 텍스트(`aria-label`)로 붙는다 |
| `prompts.md` | 캐릭터 기준 그림 프롬프트 + 컷별 이미지 AI 프롬프트(비율·크기·파일 이름, 대사 있는 컷은 말풍선 자리 비우기). 다른 그림 도구에 붙여 넣어 쓸 수도 있다. `--prompt-lang en` 이면 영어(미드저니 등에 맞춤) |
| `storyboard.md` | 콘티 표 : 컷 / 연출(배경·높이·다음 여백·자막·장면) / 등장·표정 / 대사 / 이미지 프롬프트, 맨 위에 전체 세로 길이. 사람이 검토하기 좋게 |
| `webtoon.png` | `--png` 를 주면 페이지 전체 캡처 |

종료 코드: 정상 0, 대본·배치·파일 오류 1, 잘못된 인자 2.

## 대본 형식 (요약)

```json
{
  "title": "금요일 오후 6시의 1원", "episode": 1, "width": 720,
  "style": "굵기가 일정한 깔끔한 선, 밝은 파스텔 색감 ...",
  "characters": {
    "hana": { "name": "한나", "desc": "짧은 갈색 단발에 둥근 안경 ...",
              "look": { "hair": "#6b4a3a", "hairStyle": "short", "skin": "#f3d6bd", "shirt": "#4f86c6", "glasses": true } }
  },
  "panels": [
    { "id": "p1", "height": 480, "background": "office", "caption": "금요일 오후 5시 50분",
      "scene": "사무실, 한나가 자리에서 두 팔을 들고 기뻐한다",
      "cast": [{ "who": "hana", "x": 0.5, "expression": "happy" }],
      "lines": [{ "who": "hana", "text": "급여 계산 API, 테스트 48개 전부 통과!" }] }
  ]
}
```

| 항목 | 규칙 |
|---|---|
| `width` | 360~1080 |
| `style` | 그림 분위기. 특정 작가·작품의 **화풍·그림체를 흉내 내라는 지시는 거부**(선·색감·분위기로 적는다) |
| `characters.*.look` | 색은 `#RRGGBB`, `hairStyle` 은 `short`·`long`·`bun`, `glasses` 는 선택 |
| `panels[].height` | 240~1600 |
| `panels[].gap_after` | 다음 컷까지 여백(px) 0~600, 없으면 32. 연출용 「여백 띠」(아래 「연출 규칙」) |
| `panels[].background` | `office`·`night`·`monitor`·`plain` |
| `panels[].cast[].x` | 0.1~0.9 (가로 위치 비율), `expression` 은 `neutral`·`happy`·`sad`·`surprised`·`tired` |
| `panels[].lines[]` | 말하는 사람은 그 컷의 `cast` 에 있어야 한다. 대사 하나는 60자까지 |
| 영어 필드 | `style_en`, `characters.*.desc_en`, `panels[].scene_en` 은 `--prompt-lang en` 일 때 꼭 필요하다(빠지면 경로와 함께 알림). `characters.*.name_en` 은 선택 |

## 클로드와 함께 기획하기 (스킬 `webtoon-planner`)

이 폴더에서 클로드 코드를 열고 「웹툰 1화 기획해 줘. 장르는 …, 결말은 …」처럼 말하면 스킬이 쓰인다.

1. 시놉시스 정리(빠진 것은 만들기 전에 최대 3개까지 되묻기)
2. 캐릭터 시트(외모 설명 `desc`·`desc_en` 은 이후 모든 컷에 그대로 들어가므로 짧고 구체적으로)
3. 컷 나누기 → `episodes/epNN.json`
4. 검증: `node src/cli.mjs episodes/epNN.json -o output/epNN --prompt-lang en` 이 「경고 0건」으로 끝날 때까지
5. `storyboard.md` 를 보고 사람이 고칠 점을 준다

이미지 AI(미드저니 등)를 쓸 때는 `prompts.md` 의 영어 프롬프트를 컷마다 붙여 넣고, 받은 그림은 `--images` 로 넣거나(아래) `--painter api` 어댑터로 연결한다. 말풍선은 이 도구가 코드로 얹는다.

## 연출 규칙 (여백 띠와 세로 호흡)

세로 웹툰은 독자가 내리는 속도가 곧 연출입니다. 컷마다 `gap_after` 로 다음 컷까지의 여백을 정합니다.

| 상황 | 컷 높이 | 다음 여백 |
|---|---|---|
| 빠르게 주고받는 대화 | 작게 | 좁게(0~24) |
| 반전·폭로 직전 | 보통 | 넓게(120~240) |
| 시간·장소가 바뀜 | 보통 | 넓게(160~300) |
| 감정이 터지는 큰 장면 | 크게(600~900) | 보통 |

예제 회차는 「놀라는 얼굴(2) → 160px → 모니터 공개(3)」, 「왜지?(4) → 16px → 설명(5)」, 「설명(5) → 200px → 오후 7시(6)」로 호흡을 줬습니다.
규칙 전체(한 컷에 한 가지 일, 반전은 다음 컷에, 마지막 컷 클리프행어)는 스킬 `webtoon-planner` 에 있습니다.

## 말풍선 규칙

- 화자 쪽에 놓고, 대사 순서대로 위에서 아래로 쌓는다. 그래서 겹치지 않는다.
- 모든 말풍선은 그 컷 인물의 머리보다 위에 있어야 한다. 자리가 모자라면 어느 컷인지, 몇 px 가 필요한지 알려 주고 멈춘다.
- 같은 사람이 연달아 말하면 마지막 말풍선에만 꼬리를 단다.
- 글자 폭은 추정값(한글 1, 영숫자 0.55, 공백 0.3 배)이다. 실제 글꼴로 그렸을 때 넘치지 않는지는 브라우저 테스트가 확인한다.

## 직접 만든 그림 넣기 (`--images`)

> 이미지 AI 로 그림을 받는 전체 절차(캐릭터 기준 그림 → 컷 그림 → 점검 → 조립 → 검수)는 **[실제 그림으로 웹툰 1화 완성하기 — 따라 하기](docs/실제그림_따라하기.md)** 에 단계별로 있다.

시나리오·연출은 코드 그림 콘티로 먼저 확정하고, 그래픽은 나중에 바꿔 끼우는 흐름입니다.

1. `prompts.md` 를 연다. 컷마다 프롬프트, 그림 크기(예: `크기 720×480px`), 파일 이름(예: `p1.png`)이 적혀 있다.
2. 쓰는 이미지 AI 에 컷별 프롬프트를 넣어 그림을 받는다.
3. 받은 그림을 컷 id 이름으로 한 폴더에 모은다: `art/p1.png`, `art/p2.jpg` …
4. 실행한다.

```bash
node src/cli.mjs episodes/ep01.json -o output/ep01 --images art --png
```

- 찾는 순서: `<컷 id>.png` → `.jpg` → `.jpeg` → `.webp`. 형식은 확장자가 아니라 **파일 앞부분**으로 확인한다(PNG·JPEG·WebP 만, 파일 하나 최대 10MB).
- 그림이 없는 컷, 같은 컷 파일이 여러 개인 경우, 이미지가 아닌 파일은 그 컷만 코드 그림으로 대신하고 `경고:` 로 알린다. 일부 컷만 먼저 넣어 볼 수 있다.
- 크기가 다르면 가운데를 기준으로 잘라 컷에 맞춘다. 컷 크기대로 받는 것이 가장 좋다.
- 말풍선 꼬리는 대본의 인물 위치(`cast[].x`)를 가리킨다. 프롬프트의 「위치: 왼쪽/오른쪽」대로 인물이 그려졌는지 확인하고, 다르면 그림을 다시 받거나 대본의 `x` 를 그림에 맞춘다.
- 컷 id 는 파일 이름으로 쓰이므로 영문·숫자·`_`·`-` 만 쓴다(폴더 밖 파일을 읽지 않기 위해).
- `--painter api` 와 함께 쓸 수 없다. 받은 그림 폴더는 저작권·라이선스를 확인하기 전에는 커밋하지 않는다.

## 이미지 AI 연결 (`--painter api`)

서비스마다 요청 형식이 달라서, 이 샘플은 아래의 단순한 형식만 정해 둡니다. 실제 서비스에 붙일 때는 이 형식으로 바꿔 주는 작은 중계 함수(또는 서버)를 만드세요.

```
요청: POST IMAGE_API_URL
      Authorization: Bearer IMAGE_API_KEY
      { "prompt": "...", "width": 720, "height": 480 }
응답: { "imageBase64": "...", "mimeType": "image/png" }
```

```bash
export IMAGE_API_URL=...   # 키·주소는 환경변수로만. 파일·코드에 쓰지 않는다
export IMAGE_API_KEY=...
node src/cli.mjs episodes/ep01.json -o output/ep01 --painter api
```

- 그림을 받지 못한 컷은 코드 그림으로 대신하고 `경고:` 로 알립니다. 조용히 넘어가지 않습니다.
- 응답에 이미지가 없거나 `image/png`·`image/jpeg`·`image/webp` 가 아니면 실패로 봅니다.

## 테스트

```bash
npm test     # 81개
```

- `script`: 대본 검증(없는 인물, 컷에 없는 화자, 중복 id, 색·표정, 대사 길이 경계 60/61자, 화풍 흉내 거부)
- `text`·`layout`: 줄 나누기, 말풍선이 컷 안·머리 위·겹침 없음·읽는 순서, 연속 대사 꼬리, 넘칠 때 오류
- `characters`·`prompt`: 같은 입력이면 같은 그림, 앞머리를 얼굴보다 나중에 그리기, 외모 설명을 매 컷 그대로, 글자 금지 규칙
- `render`: 대사·제목의 HTML 이스케이프(XSS), 컷 순서, 대체 텍스트, 이미지 API 성공·실패·잘못된 응답
- `cli`: 인자, 종료 코드, 예제 회차 생성
- `real-art`: 흔한 비율로 바꾸기(경계 예: 720×560 → 5:4, 720×1200 → 9:16), 대사 있는 컷에만 말풍선 자리 비우기(한국어·영어), 예제 회차의 모든 말풍선이 비워 둔 범위 안에 있는지, 캐릭터 기준 그림 프롬프트, `prompts.md` 순서
- `images`: 그림 파일 넣기(형식은 내용으로 판별, 확장자와 내용이 달라도 내용 기준, 없음·중복·이미지 아님·10MB 초과는 경고 후 코드 그림, 정확히 10MB 통과, 위험한 컷 id 는 폴더 밖을 읽지 않음, `prompts.md` 의 크기·파일 이름, CLI 인자·6컷 중 5컷만 있을 때 경고 1건·폴더 없음 종료 코드 1)
- `planning`: 영어 프롬프트(외모 설명 그대로, 글자 금지 규칙 영어, 영어 이름이 있으면 한글 없음, 영어 필드 누락 알림, 영어 화풍 흉내 거부), 콘티 표(컷당 한 줄, `|`·줄바꿈이 표를 깨지 않음), `--prompt-lang` 옵션, 기획 스킬 형식, 연출 여백(기본 32·지정값·0 허용·마지막 컷 뒤 없음·전체 세로 길이·경계 0/600 통과, -1/601/소수/문자 거부)
- `browser`(Playwright): 실제 글꼴로 그린 대사가 모두 말풍선 안에 있는지
