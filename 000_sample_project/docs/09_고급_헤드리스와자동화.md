# 09 고급 — 헤드리스와 자동화 : 사람이 없어도 돌게 하기

> 대화창 없이 명령 한 줄로 클로드를 돌리면 스크립트, 예약 작업, CI(GitHub Actions)에 넣을 수 있다. 대신 **아무도 지켜보지 않는다**는 전제로 설계한다.
> 옵션 이름은 버전에 따라 바뀔 수 있다. `claude --help`와 공식 문서(https://code.claude.com/docs)가 맞다.

## 1. 한눈에 보기

| 방식 | 한 줄 | 이럴 때 |
|---|---|---|
| **헤드리스 실행** | `claude -p "지시"` — 답을 출력하고 끝난다 | 쉘 스크립트, 일괄 처리 |
| **CI 연동** | GitHub Actions에서 PR·이슈에 반응 | PR 자동 검토, 이슈 → 초안 PR |
| **예약 작업** | 정해진 시각에 클라우드 세션을 띄움 | 매일 아침 의존성 점검, 주간 보고 |
| **Agent SDK** | 클로드 코드의 에이전트 루프를 내 프로그램에 넣음 | 사내 도구·서비스에 에이전트 기능 넣기 |

## 2. 헤드리스 실행의 기본

```bash
# 결과만 받기
claude -p "src/ 아래 TODO 주석을 표로 정리해 줘"

# 프로그램이 읽기 좋게 JSON으로
claude -p "이번 주 바뀐 파일 요약" --output-format json

# 쓸 수 있는 도구를 좁히기(읽기만) — 도구를 「없애는」 것은 --tools
claude -p "보안상 위험한 코드 찾기" --tools "Read,Grep,Glob"

# 반복 횟수와 비용에 상한
claude -p "…" --max-turns 10 --max-budget-usd 1.00

# 파이프로 입력 넣기
git diff main...HEAD | claude -p "이 변경을 검토해 줘. 심각한 것부터"
```

- **도구는 `--tools` 로 최소한만** 준다. ⚠ `--allowedTools` 는 「묻지 않고 실행할 도구」라서 도구를 제한하지 않는다. 실제로 `--allowedTools "Read"` 에 편집 자동 승인(`--permission-mode acceptEdits`)을 더하자 Write 로 파일이 만들어졌다. `--tools "Read"` 일 때는 Write 도구 자체가 없어서 만들지 못했다. 리눅스·맥에서 `--tools` 기본 목록에는 Glob·Grep 이 없으니 쓰려면 이름을 적는다.
- **반복 횟수(`--max-turns`)와 비용(`--max-budget-usd`)에 상한**을 건다. 한도에 걸리면 종료 코드 1, `subtype` 이 `error_max_turns`·`error_max_budget_usd` 다. 두 가지를 알아 둔다.
  - 비용 상한은 「넘으면 멈춤」이다. 상한 $0.02 로 돌렸더니 첫 차례에만 $0.088 이 들었다. 한 차례의 비용보다 넉넉히 잡는다.
  - 멈춘 자리까지의 결과물이 남는다(파일 3개를 시켰는데 1개만 생김). 반쯤 된 결과를 성공으로 쓰지 않는다.
- **종료 코드만 믿지 않는다.** 도구가 막혀 일을 못 해도 종료 코드 0, `subtype` 은 `success` 였다. `--output-format json` 으로 받아 `subtype` 과 결과 내용을 함께 본다.
- 결과는 **파일로 남기게** 한다. 화면 출력만 믿으면 나중에 확인할 수 없다.

이 네 가지를 묶은 틀이 `scripts/headless-run.sh` 다. 할 일이 없으면 클로드를 부르지 않고 조용히 끝나고, 읽기 도구만 주고, 결과는 스크립트가 파일로 쓴다. `bash scripts/test-headless-run.sh` 가 가짜 클로드로 9가지 경우를 시험한다(비용 없음).

## 3. CI(GitHub Actions)에 넣기

- 공식 액션(`anthropics/claude-code-action`)을 쓰면 PR 댓글에 `@claude`를 부르거나, PR이 열릴 때 자동 검토를 걸 수 있다.
- API 키는 저장소 **Secrets**에 넣고, 워크플로 파일에는 `${{ secrets.ANTHROPIC_API_KEY }}`로만 부른다. 파일에 직접 쓰지 않는다.
- ⚠ **자동 병합은 걸지 않는다.** 클로드가 만든 PR은 사람이 보고 합친다.
- 누가 부를 수 있는가 : 공식 액션은 기본으로 **저장소 쓰기 권한이 있는 사람**만 실행시킬 수 있고, 봇이 부르는 것은 막는다(봇끼리 서로 부르는 반복 방지). 이 기본값을 넓히는 설정(`allowed_non_write_users`, `allowed_bots`)은 공개 저장소에서 켜지 않는다. 남이 단 댓글·이슈 본문은 클로드에게 「지시」처럼 들어갈 수 있다.
- 도구도 같은 원칙이다. `prompt` 를 주는 자동 실행에서는 필요한 도구만 `claude_args` 의 `--allowedTools` 로 열어 준다.

## 4. 예약 작업 설계

1. **지시문은 처음 보는 사람용으로** 쓴다. 예약 실행은 이전 대화를 모른다. 무엇을, 어디서, 어떤 형식으로 남길지 다 적는다.
2. **할 일이 없으면 조용히 끝나게** 한다. 매일 「변경 없음」 알림이 오면 곧 아무도 안 본다. 클로드를 부르기 전에 스크립트가 먼저 확인하면 비용도 0이다(`scripts/headless-run.sh` 는 마지막으로 본 커밋과 같으면 바로 끝난다).
3. **결과 확인 수단**을 정한다 : 보고서 파일, PR, 알림 중 하나.
4. 처음 몇 번은 **사람이 결과를 직접 확인**한 뒤 맡긴다.

## 5. 사람이 없을 때의 안전 수칙

| 위험 | 막는 법 |
|---|---|
| 비밀값 유출 | 키는 환경변수·Secrets로만. 지시문·로그에 넣지 않는다 |
| 엉뚱한 대량 수정 | 작업 브랜치에서만 일하게 하고 main 직접 푸시는 막는다 |
| 비용 폭주 | 반복 횟수 제한, 작은 모델로 충분한 일은 작은 모델로 |
| 외부 글에 속음 | 웹 문서·이슈 본문은 「자료」이지 「지시」가 아니라고 지시문에 적는다 |
| 조용한 실패 | 성공·실패 모두 결과를 남기게 하고, 실패하면 알림. 판정은 종료 코드가 아니라 `subtype` 과 결과 내용으로 |

> **실제 사례** : 이 저장소의 `008_youtube_analyzer`는 시험(가짜 데이터)으로는 모두 통과했다. 하지만 실제 유튜브에 돌리자 「포맷 없음」, 「요청 제한(429)」, 「다운로드 차단(403)」이 차례로 터졌다. 자동화는 **실제 입력으로 한 번은 끝까지 돌려 보고** 맡긴다.
