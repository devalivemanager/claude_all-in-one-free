# 08 고급 — 훅과 권한 설계 : 「부탁」을 「강제」로 바꾸기

> CLAUDE.md는 부탁이다. 클로드가 대부분 지키지만 100%는 아니다. **반드시 지켜야 하는 것**은 권한 설정과 훅으로 옮긴다.
> 설정 이름·이벤트 이름은 버전에 따라 바뀔 수 있다. 문서와 다르면 공식 문서(https://code.claude.com/docs)가 맞다.

## 1. 한눈에 보기

| 수단 | 성격 | 이럴 때 | 위치 |
|---|---|---|---|
| **CLAUDE.md** | 부탁(대개 지킴) | 말투, 코드 습관, 작업 순서 | `CLAUDE.md` |
| **권한 규칙** | 강제(도구 호출 자체를 막거나 묻게 함) | 비밀 파일 읽기 금지, 강제 푸시 금지 | `.claude/settings.json`의 `permissions` |
| **훅** | 강제 + 자동 실행(내 스크립트가 끼어듦) | 저장 뒤 자동 정리, 위험 명령 검사, 끝내기 전 시험 확인 | `.claude/settings.json`의 `hooks` |

고르는 기준 : **어기면 사고가 나는가?** → 권한·훅. **어겨도 고치면 되는가?** → CLAUDE.md.

## 2. 설정 파일의 층

여러 곳의 설정이 겹치면 **더 좁고 더 강한 쪽**이 이긴다. 대략 이 순서다(위가 강함).

1. 회사가 배포한 관리 설정(managed) — 개인이 못 바꾼다
2. 실행할 때 준 명령줄 옵션
3. `.claude/settings.local.json` — 내 컴퓨터에서만, 커밋하지 않는다
4. `.claude/settings.json` — 팀이 같이 쓴다, 커밋한다
5. `~/.claude/settings.json` — 내 모든 프로젝트 공통

- 팀 규칙은 4번에, 내 취향은 3·5번에 둔다.
- `deny`는 어느 층에 있든 이긴다. 막아야 할 것은 `deny`로 쓴다.

## 3. 권한 규칙 짜는 법

이 틀의 `.claude/settings.example.json`이 출발점이다.

| 칸 | 뜻 | 넣을 것 |
|---|---|---|
| `deny` | 절대 못 함 | `.env`·키 파일 읽기, `git push --force`, `rm -rf` |
| `ask` | 할 때마다 물음 | `git push`, 배포, 패키지 발행 |
| `allow` | 묻지 않고 함 | `git status`·`git diff`처럼 읽기만 하는 명령, 시험 명령 |

- **처음엔 좁게** 시작해서, 매번 승인하게 되는 안전한 명령만 `allow`로 옮긴다.
- 「모든 것 허용」 모드(`bypassPermissions`)는 **버려도 되는 격리 환경**(컨테이너, 클라우드 세션)에서만 쓴다. 내 컴퓨터에서 켜지 않는다.
- ⚠ `deny`는 「그 도구로」 막는 것이다. `Read(.env)`를 막아도 `Bash(cat .env)`는 별개다. 중요한 파일은 Bash 쪽도 같이 막거나, 아예 비밀값을 저장소 밖에 둔다.

## 4. 훅

훅은 클로드가 어떤 일을 하기 **전·후**에 내 명령을 자동으로 실행한다.

| 이벤트 | 언제 | 대표 쓰임 |
|---|---|---|
| `PreToolUse` | 도구를 쓰기 직전 | 위험한 명령 검사 후 막기 |
| `PostToolUse` | 도구를 쓴 직후 | 파일을 고친 뒤 자동 정렬(포매터)·린트 |
| `UserPromptSubmit` | 내가 말을 보낸 직후 | 날짜·브랜치 같은 맥락 덧붙이기 |
| `Stop` | 클로드가 「끝」이라고 하려 할 때 | 시험 통과·커밋 여부 확인, 안 됐으면 계속 시키기 |
| `SessionStart` | 세션을 열 때 | 의존성 설치, 상태 안내 |

**막는 법** : 훅 명령이 종료 코드 `2`로 끝나면 그 동작이 막히고, 표준 에러에 쓴 글이 클로드에게 전달된다. 클로드는 그 글을 읽고 고쳐서 다시 한다.

예시는 이 틀의 `.claude/settings.hooks.example.json`에 있다.
- 파일을 고친 뒤 포매터 돌리기
- `.env`를 건드리는 Bash 명령 막기
- 끝내기 전에 커밋 안 된 변경이 있으면 알리기

> **실제 사례** : 이 저장소를 만든 클라우드 세션에는 「커밋 안 된 변경이 있으면 끝내지 못하게 하는」 `Stop` 훅이 걸려 있었다. 덕분에 작업이 컨테이너와 함께 사라지는 일이 없었다. 반대로 일부러 커밋을 미뤄야 할 때(다른 작업이 파일을 쓰는 중)는 훅이 계속 재촉했다. 그래서 「미완성 폴더를 잠시 제외 목록에 넣는다」는 우회 절차를 따로 정해야 했다. **훅을 만들 때는 예외 상황도 같이 설계한다.**

## 5. 주의

1. **훅은 내 권한으로 실행된다.** 남이 준 훅 설정은 스크립트를 한 줄씩 읽고 나서 쓴다.
2. **훅은 빨라야 한다.** 매 도구 호출마다 돌기 때문에, 몇 초씩 걸리는 훅은 작업 전체를 느리게 한다. 오래 걸리는 시험은 `Stop`에만 건다.
3. **실패 메시지를 친절하게.** 「막힘」 대신 「`npm test`가 3개 실패했다. 고친 뒤 다시 끝내라」처럼 다음 할 일을 쓴다. 클로드가 그 글을 읽고 움직인다.
4. 훅을 바꾼 뒤에는 일부러 걸리는 상황을 만들어 **정말 막히는지 시험한다.**
