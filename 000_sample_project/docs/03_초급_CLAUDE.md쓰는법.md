# 03 초급 — CLAUDE.md를 짧고 쓸모 있게 쓰는 법

> `CLAUDE.md`는 클로드가 세션마다 맨 먼저 읽는 프로젝트 규칙이다. 「천 쪽짜리 설명서」가 아니라 **「지도」**로 쓴다.

## 1. 어디에 두나

| 위치 | 적용 범위 |
|---|---|
| 프로젝트 폴더의 `CLAUDE.md` | 이 프로젝트. 팀과 함께 쓰면 저장소에 올린다 |
| `~/.claude/CLAUDE.md` | 내 컴퓨터의 모든 프로젝트(개인 습관) |
| 하위 폴더의 `CLAUDE.md` | 그 폴더를 다룰 때 추가로 읽힌다 |

## 2. 넣을 것

1. **프로젝트 한 줄 소개** — 무엇을, 어떤 기술로 만드는지
2. **실행·시험 명령** — 클로드가 스스로 확인할 수 있게
3. **절대 하면 안 되는 일** — 비밀값, 되돌릴 수 없는 작업
4. **반복해서 지적한 것** — 같은 실수를 두 번 하면 한 줄 추가
5. **자주 쓰는 경로** — 찾느라 헤매지 않게

## 3. 넣지 말 것

- 코드를 읽으면 알 수 있는 설명(폴더 구조 전체, 함수 목록)
- 가끔만 필요한 긴 절차 → `docs/`에 두고 CLAUDE.md에는 「배포는 `docs/deploy.md`를 따른다」 한 줄만
- 막연한 다짐(「좋은 코드를 쓴다」) → 확인할 수 없는 규칙은 지켜지지 않는다

## 4. 짧게 유지하는 요령

- **규칙을 하나 넣을 때 하나를 뺄 수 있는지 본다.** 길어질수록 각 줄이 덜 지켜진다.
- 「절대」, 「반드시」를 남발하지 않는다. 진짜 중요한 몇 줄에만 쓴다.
- 이유가 필요한 규칙은 한 줄 이유를 붙인다. 이유를 알면 비슷한 상황에도 맞게 판단한다.
  - 예 : 「`.env`를 읽지 않는다 — 대화 기록에 비밀값이 남는다」

## 5. 키우는 방법

1. `/init`으로 초안을 만든다.
2. 일을 시키다가 클로드가 틀리면 「이걸 CLAUDE.md에 한 줄로 추가해 줘」라고 한다.
3. 한 달에 한 번 훑어보고, 더는 필요 없는 줄을 지운다.

## 6. 점검표

- [ ] 실행·시험 명령이 적혀 있다
- [ ] 비밀값 규칙이 있다
- [ ] 한 화면(약 50~100줄) 안에 들어온다
- [ ] 모든 줄이 「확인할 수 있는」 규칙이다
