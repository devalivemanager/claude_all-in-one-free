# 04 중급 — 스킬, 서브에이전트, MCP 언제 무엇을 쓰나

> 셋 다 「클로드에게 능력을 더하는 방법」이지만 쓰임이 다르다. 헷갈리면 아래 표부터 본다.

## 1. 한눈에 비교

| 도구 | 한 줄 | 이럴 때 | 위치 |
|---|---|---|---|
| **CLAUDE.md** | 늘 지키는 규칙 | 모든 작업에 적용되는 것 | 프로젝트 맨 위 |
| **스킬** | 필요할 때 꺼내 쓰는 절차서 | 정해진 순서가 있는 반복 작업(배포, 점검, 글 발행) | `.claude/skills/<이름>/SKILL.md` |
| **서브에이전트** | 따로 일하고 결과만 돌려주는 조수 | 많이 읽어야 하지만 결론만 필요한 일, 독립적인 검토 | `.claude/agents/<이름>.md` |
| **MCP** | 바깥 프로그램과 연결하는 통로 | 브라우저, 데이터베이스, 디자인 도구, 문서 서비스 | `claude mcp add ...` |

## 2. 스킬

- 폴더 하나에 `SKILL.md` 하나. 맨 위 `name`과 `description`이 핵심이다. 클로드는 평소에 **설명만** 보고 있다가 맞는 상황이 오면 본문을 읽는다.
- 그래서 `description`에는 「언제 쓰는지」와 사용자가 실제로 쓸 말(「배포해 줘」, 「마무리」)을 넣는다.
- 예시 : 이 틀의 `.claude/skills/done-check/`. 「완료 확인해 줘」라고 하면 불려 온다.
- 스킬 설명은 모든 세션에 실리므로 **자주 쓰는 것만** 깐다. 안 쓰는 스킬은 지우거나 다른 곳에 보관한다.

## 3. 서브에이전트

- 별도의 대화 공간에서 일하고 **요약만** 돌려준다. 그래서 내 대화가 파일 내용으로 가득 차지 않는다.
- 예시 : 이 틀의 `.claude/agents/reviewer.md`. 읽기 전용 도구만 줘서 고치지 못하게 했다.
- `/agents`로 목록을 보고 만들 수 있다.
- ⚠ **공짜가 아니다.** 서브에이전트는 내 대화 맥락을 모르니 지시문을 자세히 써야 하고, 그만큼 토큰이 든다. 파일 몇 개짜리 일은 직접 시키는 편이 싸고 빠르다. 대량으로 읽거나 서로 독립인 일을 동시에 돌릴 때 이득이다.

## 4. MCP

- `claude mcp add <이름> ...`으로 연결하고, 세션 안에서 `/mcp`로 상태를 본다.
- 처음 붙여 볼 만한 것 : 브라우저 자동화, 라이브러리 최신 문서 조회, 쓰는 디자인·문서 도구.
- ⚠ 연결 전에 확인할 것
  1. 누가 만들었고 무엇을 읽고 쓸 수 있는지
  2. 무료인지, 계정 연결(로그인)이 필요한지
  3. 설치 안내 문서를 **사람이 먼저 읽었는지** — 「이 링크를 붙여 넣으면 알아서 설치」 방식은 클로드가 남의 문서를 그대로 따라 하게 만든다
- MCP 도구 설명도 매 세션 맥락을 차지한다. 안 쓰는 연결은 끈다.

## 5. 고르는 순서

1. 매번 지켜야 하나? → CLAUDE.md 한 줄
2. 가끔, 정해진 순서로 하나? → 스킬
3. 많이 읽어야 하는데 결론만 필요한가? 독립적인 눈이 필요한가? → 서브에이전트
4. 클로드 밖의 프로그램을 만져야 하나? → MCP
