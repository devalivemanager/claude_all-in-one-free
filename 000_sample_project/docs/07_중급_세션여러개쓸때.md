# 07 중급 — 세션을 여러 개 쓸 때 꼬이지 않는 법

> 익숙해지면 세션을 두세 개 동시에 띄우게 된다. 같은 파일을 둘이 고치기 시작하면 한쪽 작업이 조용히 사라질 수 있다.
>
> 시험 : 두 세션이 같은 폴더의 같은 파일 끝에 동시에 한 줄씩 넣게 했다. 클로드 코드의 편집 도구가 「읽은 뒤 바뀐 파일」을 알아채서 두 줄 다 남았다. 하지만 이 검사는 클로드 코드의 편집 도구에만 있다. 사람이 연 편집기, 포매터, Bash 로 파일을 쓰는 스크립트는 그냥 덮어쓴다. 그리고 「줄이 둘 다 남았다」와 「둘이 같은 방향으로 고쳤다」는 다르다. 아래 규칙은 그대로 지킨다.

## 1. 기본 규칙 네 가지

1. **세션마다 맡을 영역을 나눈다.** 예 : 한 세션은 `src/api/`, 다른 세션은 `src/ui/`. 같은 파일을 두 세션이 고치지 않는다.
2. **같은 저장소를 동시에 고쳐야 하면 작업 폴더를 나눈다.** git worktree로 브랜치마다 폴더를 따로 만들면 서로 덮어쓰지 않는다. 같은 줄을 고쳤다면 합칠 때 **충돌로 드러나서** 사람이 고른다(시험에서도 그랬다).
3. **세션끼리 대화시키지 말고 파일로 넘긴다.** 「인계 메모」 파일에 무엇을 했고, 무엇을 부탁하며, 해 봤는데 안 된 것이 무엇인지 적는다. 다른 세션은 그 파일을 읽는다.
4. **공용 파일은 한 세션만 고친다.** `CLAUDE.md`, 설정 파일, 패키지 목록(`package.json` 등)은 「주인 세션」을 하나 정한다.

## 2. 인계 메모 틀

```markdown
# 인계 : [무슨 일] (YYYY-MM-DD)

- 무슨 일 : 
- 부탁 : 
- 해 봤는데 안 된 것 : 
- 처리 결과 : (받은 세션이 채운다)
```

「안 된 것」 칸이 중요하다. 이것이 없으면 받은 세션이 같은 실패를 되풀이한다.

## 3. 백그라운드로 보낼 일, 앞에 둘 일

- **앞에 둘 일** : 중간중간 내가 확인하고 결정해야 하는 일
- **뒤로 보낼 일** : 혼자 오래 도는 일(긴 시험, 대량 변환). 끝나면 결과 파일을 남기게 한다
- 기준은 시간이 아니라 「대화를 붙잡고 있을 이유가 있는가」다.

## 4. 꼬였을 때

1. 모든 세션을 멈춘다(`Esc`).
2. `git status`, `git diff`로 실제로 무엇이 바뀌었는지 본다.
3. 한 세션에서만 정리하고, 나머지는 `/clear` 후 인계 메모를 읽고 다시 시작한다.
