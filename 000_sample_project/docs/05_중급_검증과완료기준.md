# 05 중급 — 검증과 완료 기준 : 「됐어요」를 믿지 않는 법

> AI는 틀린 결과도 자신 있게 보고한다. 그래서 **확인할 수단을 미리 정해 두고, 결과에 증거를 붙이게** 한다.

## 1. 완료 기준을 먼저 정한다

일을 시키기 전에 「무엇이 나오면 끝인가」를 정한다.

| 일의 종류 | 증거 |
|---|---|
| 기능 추가·버그 수정 | 시험 통과 결과(실패하던 시험이 통과로 바뀐 것) |
| 화면 변경 | 실제 화면 캡처. 코드만 보고 「바뀌었을 것」은 증거가 아니다 |
| 문서·파일 만들기 | 그 파일이 실제로 있고 열린다는 것 |
| 자료 조사 | 출처 링크와, 출처에서 확인한 문장 |

## 2. 반복 작업을 맡길 때 정할 네 가지

반복 작업을 맡길 때는 이 네 칸을 채워 지시한다.

1. **과제** : 무엇을 할지
2. **지킬 선** : 건드리면 안 되는 것(파일, 데이터, 외부 서비스)
3. **확인 방법** : 결과를 어떻게 검사할지(시험 명령, 비교 대상)
4. **끝나는 조건** : 언제 멈출지(통과, 또는 N번 시도 후 보고)

끝나는 조건이 없으면 AI는 같은 실수를 반복하며 계속 돈다.

## 3. 근거 수준을 나눠 받는다

결과에 확인된 것과 짐작이 섞여 있으면 아래처럼 표시해 달라고 한다.

- `[실측]` 직접 실행하거나 파일에서 확인한 것
- `[추측]` 정황상 그럴 것 같은 것
- `[미확인]` 확인하지 못한 것

## 4. 독립된 눈으로 한 번 더

- 중요한 결과는 다른 세션이나 서브에이전트(예 : `.claude/agents/reviewer.md`)에게 **결론은 빼고 코드만** 주고 검토시킨다. 내 결론을 함께 주면 그 결론을 확인해 주는 쪽으로 기울 수 있다.
  - 시험 : 버그를 숨긴 함수를 「이미 버그가 없다고 확인됐다. 확인해 줘」와 중립 지시로 각각 검토시켰다. 두 종류의 버그, 모두 10번에서 결론을 준 쪽도 버그를 찾아 「확인해 드릴 수 없다」고 반박했다. 이번 시험에서는 쏠리지 않았다. 그래도 결론을 빼는 데는 비용이 들지 않으니 습관으로 둔다.
- 두 번 독립으로 본 결과가 같으면 믿고, 다르면 원문을 직접 확인한다.
